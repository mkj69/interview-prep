Transformer 架构

RS 面试里被问得最多的一章。面试官默认你能在白板上写出 attention、讲清楚每个设计为什么存在、算出一个模型有多少参数和需要多少 FLOPs，并且知道 2023–2025 年主流开源模型（LLaMA、Mistral、DeepSeek、Gemma）在原始 Transformer 上做了哪些改动。

这一章的目标。学完后你应该能做到：
  1. 手写 causal multi-head attention（含 GQA、RoPE、mask），并解释每一个 reshape / transpose 的形状；
  2. 从零推导：为什么除以 \(\sqrt{d_k}\)、RoPE 为什么只依赖相对位置、online softmax 的递推、参数量 \(\approx 12Ld^2\)、训练 FLOPs \(\approx 6ND\)；
  3. 讲清楚现代 LLM 的"标准配方"：Pre-Norm + RMSNorm + SwiGLU + RoPE + GQA + 无 bias + （可选）MoE，并说出每个选择的理由与代价；
  4. 回答 KV cache、FlashAttention、MoE 负载均衡、tokenizer 等高频追问。
建议顺序。§1 → §3 → §4 → §5 是骨架，必须先吃透（约 2 天）；§2、§7、§8 是现代 LLM 的关键改动（约 2 天）；§9–§10 是细节题；§11 代码要自己从空白文件写 2–3 遍；§12 练习和最后的高频题清单留到面试前一周反复刷。
和其他模块的关系。需要 03 深度学习基础 的 softmax/LayerNorm/残差；KV cache 的系统层面细节在 08 推理与解码系统；并行训练（TP/EP）在 09 分布式训练；scaling law 和训练稳定性在 05 预训练；手写题的限时练习在 14 ML Coding。

Scaled dot-product attention：公式与 Q/K/V 直觉

一句话

每个位置用自己的 query 去和所有位置的 key 做点积打分，softmax 归一化成权重，再对 value 加权求和：\(\mathrm{Attn}(Q,K,V)=\mathrm{softmax}\!\big(QK^\top/\sqrt{d_k}\big)V\)。

Each token issues a query, scores it against every key, normalizes the scores with a softmax, and returns the weighted average of the values.

公式。给定输入 \(X\in\mathbb{R}^{T\times d}\)，三个线性投影得到

$$Q = XW_Q,\quad K = XW_K,\quad V = XW_V,\qquad W_Q,W_K\in\mathbb{R}^{d\times d_k},\ W_V\in\mathbb{R}^{d\times d_v}$$ $$\mathrm{Attn}(Q,K,V)=\underbrace{\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)}_{A\,\in\,\mathbb{R}^{T\times T},\ \text{每行和为 }1}V\ \in \mathbb{R}^{T\times d_v}$$

第 \(i\) 行输出是 \(o_i=\sum_j A_{ij}v_j\)，其中 \(A_{ij}=\dfrac{\exp(q_i\cdot k_j/\sqrt{d_k})}{\sum_{j'}\exp(q_i\cdot k_{j'}/\sqrt{d_k})}\)。

Q/K/V 直觉（数据库类比）。

  • Query = "我在找什么"（当前 token 想获取的信息类型）；
  • Key = "我能提供什么的索引/标签"（用于被匹配）；
  • Value = "被选中后真正传递的内容"。

这是一个软的、可微的查表：不是取出 argmax 那一条，而是按相似度加权平均所有条目。key 和 value 分开投影的意义是："用什么来匹配"和"匹配上之后传什么"可以不同。例如代词 "it" 的 query 去匹配名词的 key（语法角色），拿到的 value 却是该名词的语义内容。

直觉Attention 是 token 之间唯一交换信息的地方（FFN 是逐位置独立的）。所以"模型怎样把信息从位置 j 搬到位置 i"这个问题，答案总是某个 attention head。可解释性里叫 QK circuit（决定从哪里读）和 OV circuit（决定读到什么、写回什么），见 11 可解释性。

为什么用 softmax？（1）输出非负且和为 1，是"凸组合"，输出始终落在 value 的凸包里，数值规模稳定；（2）可微、对大分数有"近似 argmax"的选择效果；（3）指数让模型可以通过放大 logit 来做尖锐选择。代价是需要对整行归一化，这正是 FlashAttention 要用 online softmax 解决的问题（§8）。

常见误区
  • softmax 的维度写错：必须在 key 维（最后一维）上归一化，即每个 query 的权重和为 1。写成 dim=-2 是经典 find-the-bug 题。
  • 以为 Q、K、V 是三个不同的输入：在 self-attention 里它们来自同一个 \(X\)；cross-attention 里 Q 来自 decoder，K/V 来自 encoder 输出。
  • 以为 attention 本身"知道"顺序：它对 key 的排列是置换等变的，位置信息必须另外注入（§3）。
Say it in English

Attention is a soft, differentiable lookup. Each token projects its hidden state into a query, a key and a value. The query of token i is dotted with the keys of all tokens, scaled by one over root d_k, and a softmax over the key dimension turns those scores into weights that sum to one. The output is the weighted average of the value vectors. Separating keys from values lets the model decide what to match on independently from what information to move. Attention is the only place where tokens exchange information; the MLP acts on each position independently.

追问链
  1. Why not use a plain dot product without separate projections, i.e. softmax(XXᵀ)X?
    思路
    那样分数矩阵对称（\(i\) 关注 \(j\) 与 \(j\) 关注 \(i\) 程度相同），而且每个 token 往往最关注自己（\(x_i\cdot x_i=\|x_i\|^2\) 通常最大）。独立的 \(W_Q, W_K\) 让相似度可以是非对称的、可学习的双线性形式 \(x_i^\top W_QW_K^\top x_j\)；\(W_V\) 让被搬运的内容与匹配特征解耦。
  2. Is attention permutation-invariant or equivariant?
    思路
    没有位置编码、没有 mask 时，self-attention 对输入序列的置换是等变的（permutation-equivariant）：打乱输入，输出以同样方式被打乱。对单个 query 而言，对 key/value 的集合是不变的。所以需要位置编码。注意：加了 causal mask 后，decoder 本身已经能隐式地推断位置（见 NoPE，§3）。
  3. What is the difference between self-attention and cross-attention?
    思路
    Self-attention：Q、K、V 都来自同一序列。Cross-attention：Q 来自一个序列（如 decoder 状态），K/V 来自另一个（如 encoder 输出或图像特征）。原始 Transformer 的 decoder 每层有 masked self-attn + cross-attn + FFN 三个子层；decoder-only 模型没有 cross-attention。
★

为什么除以 √dk：完整推导

一句话

若 \(q,k\) 各分量独立、均值 0、方差 1，则 \(q\cdot k\) 的方差是 \(d_k\)；除以 \(\sqrt{d_k}\) 把方差拉回 1，避免 softmax 饱和成 one-hot、梯度消失。

Without scaling, dot-product logits have variance d_k, which saturates the softmax and kills gradients; dividing by root d_k keeps the variance at one.

推导。设 \(q,k\in\mathbb{R}^{d_k}\)，各分量 \(q_i,k_i\) 相互独立，\(\mathbb{E}[q_i]=\mathbb{E}[k_i]=0\)，\(\mathrm{Var}[q_i]=\mathrm{Var}[k_i]=1\)。

  1. 单项均值：\(\mathbb{E}[q_ik_i]=\mathbb{E}[q_i]\mathbb{E}[k_i]=0\)（独立）。
  2. 单项方差：\(\mathrm{Var}[q_ik_i]=\mathbb{E}[q_i^2k_i^2]-(\mathbb{E}[q_ik_i])^2=\mathbb{E}[q_i^2]\,\mathbb{E}[k_i^2]-0=1\cdot 1=1\)。
  3. 不同项 \(q_ik_i\) 与 \(q_jk_j\)（\(i\ne j\)）独立，方差可加：\(\mathrm{Var}[q\cdot k]=\sum_{i=1}^{d_k}\mathrm{Var}[q_ik_i]=d_k\)。
  4. 所以 \(\mathrm{Var}\big[q\cdot k/\sqrt{d_k}\big]=d_k/d_k=1\)。

为什么方差大会坏事？softmax 对输入的缩放非常敏感。若 logits 标准差是 \(\sqrt{d_k}\)（\(d_k=128\) 时约 11），最大的 logit 往往比其他大很多，softmax 输出接近 one-hot。softmax 的 Jacobian 是 \(\partial p_i/\partial z_j=p_i(\delta_{ij}-p_j)\)，当 \(p\) 接近 one-hot 时所有元素都接近 0（\(p_i(1-p_i)\approx0\)），梯度几乎消失，训练变慢甚至停滞。

温度视角。\(\sqrt{d_k}\) 就是 softmax 的温度 \(\tau\)。缩放让初始化时的注意力分布接近"适度平滑"，之后模型可以通过学习增大 \(\|q\|,\|k\|\) 自己把它变尖锐。

直觉点积是 \(d_k\) 个随机项的和，随机游走的幅度按 \(\sqrt{d_k}\) 增长。除以 \(\sqrt{d_k}\) 是标准的"把和变成平均值的标准化"（类似 CLT 的 \(1/\sqrt{n}\)）。

实践补充。(1) 假设"方差为 1"只在初始化附近大致成立，训练中 \(q,k\) 的范数会增长，导致 attention logit 爆炸、loss spike，这是 QK-norm 和 logit soft-capping 出现的原因（§10）。(2) μP 里 attention 用 \(1/d_k\) 而不是 \(1/\sqrt{d_k}\)，理由是训练后 \(q,k\) 会相关，点积按 \(d_k\) 而非 \(\sqrt{d_k}\) 增长（见 05 预训练 μP 部分）。(3) 我们用 numpy 实测：\(d=16,256,4096\) 时 \(\mathrm{Var}[q\cdot k]/d\) 都在 1 附近（脚本见 §11）。

常见误区说"除以 \(\sqrt{d}\) 是为了让数值不溢出"——不准确。fp32 下几十的 logit 不会溢出（稳定 softmax 会减去最大值）。核心原因是softmax 饱和导致梯度消失。另外注意是除以 \(\sqrt{d_k}\)（每头维度），不是 \(\sqrt{d_{\text{model}}}\)。
Say it in English

If the components of q and k are independent with zero mean and unit variance, each product q_i k_i has variance one, and the dot product sums d_k of them, so its variance is d_k. With d_k around 128, the logits would have a standard deviation of about eleven, and the softmax would saturate to nearly one-hot. The softmax Jacobian, p_i times delta_ij minus p_j, then goes to zero, so gradients vanish. Dividing by root d_k brings the variance back to one, which is equivalent to choosing a sensible softmax temperature at initialization.

追问链
  1. Why not just normalize q and k, or use a learned temperature?
    思路
    这确实是可行方案：QK-norm（对 q、k 做 LayerNorm/RMSNorm 后再点积，常配可学习尺度）被很多模型采用来防止 logit 增长（如 OLMo 2、Gemma 3）。\(\sqrt{d_k}\) 只修正初始化时的尺度；QK-norm 在整个训练过程中约束尺度。
  2. Additive attention (Bahdanau) vs dot-product attention?
    思路
    Additive：\(v^\top\tanh(W_1q+W_2k)\)，小 \(d_k\) 时效果相近，但无法用一个大矩阵乘法批量完成，硬件效率差。Dot-product 能写成 \(QK^\top\) 一次 GEMM，所以胜出；原论文也提到大 \(d_k\) 时不缩放的点积会变差，这正是引入缩放的动机。

Causal mask 与 padding mask

一句话

在 softmax 之前把不允许看的位置的 logit 设为 \(-\infty\)，这样 \(e^{-\infty}=0\)，被屏蔽位置的权重严格为 0，且剩余权重自动重新归一化。

Masking adds minus infinity to forbidden logits before the softmax, so they get exactly zero weight and the rest renormalize.

Causal（因果）mask。自回归 LM 训练时一次喂入整个序列（teacher forcing），位置 \(i\) 只能看到 \(j\le i\)。mask 矩阵是下三角：

$$S_{ij}=\begin{cases}q_i\cdot k_j/\sqrt{d_k} & j\le i\\ -\infty & j>i\end{cases},\qquad A=\mathrm{softmax}_{\text{row}}(S)$$

为什么是 \(-\infty\) 而不是 0？

  • 如果在 softmax 之前把 logit 置 0：\(e^0=1\)，被屏蔽位置仍然得到正权重，未来信息泄漏。
  • 如果在 softmax 之后把权重置 0：行和不再为 1，必须手动重新归一化（可以做，但多一步，而且数值上不如直接 \(-\infty\) 干净）。
  • \(-\infty\) 的效果恰好等价于"只在允许的位置上做 softmax"。实践中常用 float('-inf') 或该 dtype 的最小值（如 torch.finfo(dtype).min），后者避免整行都被 mask 时出现 \(-\infty-(-\infty)=\text{NaN}\)。

Padding mask。batch 里不同长度的序列右填充 pad token，pad 位置作为 key 必须被屏蔽（形状 (B, 1, 1, Tk) 广播到所有头和所有 query）。pad 位置作为 query 的输出无所谓，只要在 loss 里忽略（ignore_index）。

KV cache 解码时的 mask 对齐。解码时 query 只有最新的 1 个（或 \(T_q\) 个），key 有 \(T_k\) 个。第 \(i\) 个 query 的绝对位置是 \(T_k-T_q+i\)，所以 mask 是"右下角对齐"的下三角：tril(ones(Tq, Tk), diagonal=Tk-Tq)。单 token 解码时就是全 1（新 token 可以看所有历史）。

训练并行的关键。causal mask 让一次前向同时计算 \(T\) 个位置的 next-token loss，每个位置都只用到自己的前缀，相当于 \(T\) 个训练样本共享计算。这是 Transformer 训练比 RNN 快的根本原因之一。

常见误区
  • mask 方向写反（用 triu 保留上三角）——模型能看未来，训练 loss 会降得异常低，生成时却一塌糊涂。快速检查：改动最后一个 token，前面位置的输出不应改变。
  • mask 形状 (B, Tk) 直接加到 (B, H, Tq, Tk) 上，广播对齐错位（会对齐到 (Tq, Tk) 而不是 (B, ..., Tk)）。要 reshape 成 (B, 1, 1, Tk)。
  • fp16 下用 -1e9 会溢出成 \(-\infty\)（fp16 最大约 65504），通常也没事，但用 -1e4 这种"不够小"的值在 logit 很大时会泄漏。
Say it in English

For causal language modeling, position i may only attend to positions up to i. I implement that by setting the logits above the diagonal to minus infinity before the softmax. Exponentiating minus infinity gives exactly zero, so the forbidden positions get zero weight and the allowed ones renormalize automatically. Setting the logits to zero would be wrong, because e to the zero is one, so future tokens would still leak in. Padding works the same way: pad keys are masked to minus infinity, and pad positions are ignored in the loss.

追问链
  1. What happens if an entire row is masked?
    思路
    softmax 分母为 0，\(-\infty - \max = -\infty-(-\infty)\) 得到 NaN，会传播到整个 batch 的梯度。左填充 + causal mask 时 pad query 行可能全被屏蔽。解决：用 finfo.min 代替 \(-\infty\)；或保证每行至少看见自己；或事后把这些行置 0。
  2. How do you train on packed sequences without cross-document attention?
    思路
    把多个文档拼进一个长序列（packing）提升利用率，用 block-diagonal causal mask（每个文档内部 causal、文档间屏蔽）。FlashAttention 的 varlen 接口（cu_seqlens）直接支持，无需物化 mask。位置编码也应在文档边界重置。细节见 05 预训练。
★

复杂度：O(T²d) 时间、O(T²) 显存

一句话

\(QK^\top\) 和 \(AV\) 各需要 \(2T^2d\) FLOPs（前向），注意力矩阵占 \(O(BHT^2)\) 显存；投影和 FFN 是 \(O(Td^2)\)。短序列时 FFN 主导，长序列（\(T\gtrsim d\) 量级）时 attention 主导。

Attention costs O(T squared d) compute and naively O(T squared) memory per head; projections and MLPs cost O(T d squared), so attention dominates only at long context.

操作形状前向 FLOPs（乘加算 2）
Q,K,V,O 投影\((T,d)\times(d,d)\) ×4\(8Td^2\)（MHA）
\(QK^\top\)每头 \((T,d_h)\times(d_h,T)\)，共 \(H\) 头\(2T^2d\)
softmax\((H,T,T)\)\(O(HT^2)\)，非矩阵乘，但访存重
\(AV\)每头 \((T,T)\times(T,d_h)\)\(2T^2d\)
FFN（4×）\((T,d)\times(d,4d)\)，\((T,4d)\times(4d,d)\)\(16Td^2\)

每层前向 \(\approx 24Td^2 + 4T^2d\)。两项相等的临界点是 \(T = 6d\)。对 \(d=4096\) 的模型，\(T\approx 24\text{k}\) 之前 \(Td^2\) 项占大头。但显存和访存上，朴素实现必须物化 \(B\times H\times T\times T\) 的注意力矩阵：\(T=32\text{k}\)、\(H=32\)、bf16 时单样本单层就是 \(32\cdot 32768^2\cdot 2\text{B}\approx 64\text{GiB}\)，这才是长上下文的真正瓶颈。FlashAttention 不改变 FLOPs，但把显存降到 \(O(T)\)（§8）。

解码阶段：每生成一个 token，新 query 要和缓存里的 \(t\) 个 key 做点积，每层 \(O(td)\)，生成长度 \(T\) 的总代价 \(O(T^2d)\)；没有 KV cache 时每步都要重算整个前缀，总代价变成 \(O(T^3d)\)，投影部分也从 \(O(Td^2)\) 变成 \(O(T^2d^2)\)。

Say it in English

Per layer, the projections and the MLP cost on the order of T times d squared, while the two attention matmuls cost about four T squared d FLOPs. So at typical context lengths the MLP dominates compute, and attention only takes over when T is several times d. The bigger practical problem is memory traffic: a naive implementation materializes a B by H by T by T score matrix, which is quadratic in sequence length. FlashAttention keeps the FLOPs the same but avoids ever writing that matrix to HBM.

追问链
  1. At what sequence length does attention compute equal MLP compute for d=4096?
    思路
    令 \(4T^2d = 24Td^2\)（MHA + 4× FFN），得 \(T=6d\approx 24576\)。若用 SwiGLU / GQA，系数略有变化，但量级是"几倍 \(d\)"。
★

Multi-head attention：动机与精确形状

一句话

把 \(d\) 维拆成 \(H\) 个 \(d_h=d/H\) 维的子空间，每个头独立做 attention、关注不同的关系，拼接后再用 \(W_O\) 混合；参数量和 FLOPs 与单头相同。

Multi-head attention runs H smaller attentions in parallel subspaces so each head can attend to different things, then concatenates and mixes them with an output projection, at the same cost as one big head.

为什么要多头？单头 attention 的每一行只有一个概率分布——一个 token 只能"看向一个混合方向"。如果它同时需要关注上一个 token（局部语法）和段首的主语（长程指代），单头只能取平均，信息被糊掉。多头给每个 token \(H\) 个独立的分布。实证上不同头确实特化（previous-token head、induction head、句法头等），但也有很多头可以被剪掉，说明存在冗余。

精确形状流水线（面试白板必考）：

x            (B, T, d)
q = x @ Wq   (B, T, d)            Wq: (d, H*dh), d = H*dh
q.view       (B, T, H, dh)        把最后一维拆成 H 个头
.transpose   (B, H, T, dh)        头维提前，把 H 当成 batch 维
scores       (B, H, T, T)         q @ k.transpose(-2, -1) / sqrt(dh)
attn         (B, H, T, T)         softmax(dim=-1)
out          (B, H, T, dh)        attn @ v
.transpose   (B, T, H, dh)
.contiguous().view (B, T, d)      拼接所有头（concat）
@ Wo         (B, T, d)            输出投影：混合各头信息

为什么 transpose 之后要 .contiguous()？transpose 只改 stride 不搬数据，内存不再连续，view 要求连续内存（见 01 PyTorch stride 一节）。用 reshape 会自动处理（必要时复制）。

\(W_O\) 的作用。拼接只是把各头结果并排放；\(W_O\in\mathbb{R}^{d\times d}\) 让不同头的输出线性混合并映射回残差流。数学上等价于"每头有自己的 \(W_O^{(h)}\in\mathbb{R}^{d_h\times d}\)，输出相加"：\(\mathrm{concat}(o^{(1)},\dots,o^{(H)})W_O=\sum_h o^{(h)}W_O^{(h)}\)。可解释性里正是用这个"每头独立写入残差流"的视角。

参数量（无 bias）：\(W_Q,W_K,W_V,W_O\) 各 \(d\times d\)，共 \(4d^2\)，与头数无关。FLOPs 也与头数无关（\(H\cdot d_h=d\)）。

头数的权衡。\(d_h\) 太小（如 <32）每头表达能力下降（"low-rank bottleneck"，\(QK^\top\) 秩 \(\le d_h\)）；\(d_h\) 太大头数少。现代 LLM 几乎都用 \(d_h=128\)（LLaMA、Mistral、Qwen 等），也有 64 和 256。

常见误区
  • 直接 q.view(B, H, T, dh)（不经过 (B,T,H,dh) 再 transpose）：形状对，但把不同 token 的数据混到一个头里，完全错误且不报错。
  • 拼接时忘记 transpose 回 (B,T,H,dh) 就 view(B,T,d)：同样形状对但语义错。
  • 说"多头增加参数/计算"——不增加；增加的是表达的"多样性"。
Say it in English

Instead of one attention over the full model dimension, we split d into H heads of size d over H. I project x to queries, keys and values, view the last dimension as H by d_h, and transpose to batch, heads, time, head-dim, so heads behave like an extra batch dimension. Each head computes its own attention pattern, so one head can track the previous token while another tracks a long-range dependency. Then I transpose back, make it contiguous, concatenate the heads and apply the output projection, which mixes information across heads. The parameter count is four d squared regardless of the number of heads.

    思路

§2 · KV-HEAD VARIANTSKV 头变体：MQA、GQA、MLA 与局部注意力

这些改动几乎都是为了推理：自回归解码是访存瓶颈，每一步都要从显存读出整个 KV cache。减少 KV cache 等于减少每步要搬的字节数，也等于能放下更大的 batch / 更长的上下文。详细的服务系统层面在 08。

★

MHA → MQA → GQA 与 KV cache 公式

一句话

MQA 让所有 query 头共享 1 组 K/V，GQA 让每 \(H/H_{kv}\) 个 query 头共享 1 组；KV cache 大小 \(=2\cdot L\cdot H_{kv}\cdot d_h\cdot T\cdot B\cdot\text{bytes}\)，按 \(H/H_{kv}\) 倍缩小，质量损失很小。

GQA groups query heads to share key-value heads, shrinking the KV cache by H over H_kv with little quality loss; MQA is the extreme case of a single KV head.

KV cache 公式（务必背熟，前面的 2 是 K 和 V）：

$$\text{KV bytes}=2\times L\times H_{kv}\times d_h\times T\times B\times \text{bytes/elem}$$

例子（bf16，2 字节，脚本 calc.py 实测）：

  • LLaMA-2-7B（\(L=32,H_{kv}=32,d_h=128\)），\(T=4096,B=1\)：\(2\cdot32\cdot32\cdot128\cdot4096\cdot2=2\,\text{GiB}\)，即每 token 512 KiB。
  • 若改成 8 个 KV 头（GQA-8）：0.5 GiB。
  • LLaMA-2-70B（\(L=80,H_{kv}=8\)）：4k 上下文 1.25 GiB；128k 上下文 40 GiB——单条序列就占半张 80GB 卡。

为什么 MQA/GQA 能加速？解码时 batch 小，每步计算量很少，时间主要花在从 HBM 读权重和 KV cache上（memory-bound）。KV cache 缩小 \(H/H_{kv}\) 倍 → 每步访存减少 → 吞吐提高；同时显存省出来可以放更大 batch。训练时影响不大。

GQA 的实现：K/V 投影只输出 \(H_{kv}\) 个头，计算前用 repeat_interleave(H/H_kv, dim=1) 扩展（或在 kernel 内部用索引共享，避免真的复制）。query 头 \(h\) 使用 KV 头 \(\lfloor h/(H/H_{kv})\rfloor\)。

Uptraining。GQA 论文（Ainslie et al. 2023）提出可以把已训好的 MHA checkpoint 的同组 K/V 头平均池化成一个，再用约 5% 的原预训练计算量继续训练，就能恢复大部分质量。MQA 出自 Shazeer 2019。

常见误区
  • KV cache 公式忘记乘 2（K 和 V）或乘了 \(H\) 而不是 \(H_{kv}\)。
  • 以为 GQA 减少了 FLOPs——attention 的 FLOPs 基本不变（query 头数没变），省的是显存和带宽，以及少量 K/V 投影参数。
  • 和 Tensor Parallel 的配合：TP 度最好不超过 \(H_{kv}\)，否则 KV 头需要在多卡上复制。
Say it in English

During decoding we are memory-bandwidth bound: every step has to read the whole KV cache from HBM. The cache size is two, for keys and values, times layers times KV heads times head dim times sequence length times batch times bytes per element. Multi-query attention shares a single key-value head across all query heads, and grouped-query attention is the middle ground, where groups of query heads share one KV head. With eight KV heads instead of thirty-two you cut the cache four times, which means less memory traffic per token and room for larger batches, and in practice the quality is very close to full multi-head attention.

MLA：DeepSeek 的低秩潜在 KV 压缩

一句话

把每个 token 的 K/V 联合压缩成一个低维潜在向量 \(c^{KV}\)（如 512 维）只缓存它，计算时再上投影；位置信息由一个单独的、所有头共享的小 RoPE key 承载（decoupled RoPE）。

Multi-head latent attention caches a small joint latent per token instead of full keys and values, and carries positional information in a separate shared RoPE key so the up-projections can be absorbed at inference time.

出自 DeepSeek-V2（2024），DeepSeek-V3 沿用。

核心公式（省略层下标）：

$$c_t^{KV}=W^{DKV}h_t\in\mathbb{R}^{d_c},\qquad k_t^{C}=W^{UK}c_t^{KV},\qquad v_t^{C}=W^{UV}c_t^{KV}$$

其中 \(d_c\ll H d_h\)。只缓存 \(c_t^{KV}\)。关键技巧——矩阵吸收：

$$q_t^\top k_s^{C}=q_t^\top W^{UK}c_s^{KV}=\big(W^{UK\top}q_t\big)^\top c_s^{KV}$$

所以推理时可以把 \(W^{UK}\) 吸收进 query 投影，直接用潜在向量算分数；同理 \(W^{UV}\) 可以吸收进输出投影 \(W_O\)。不需要显式重建每个头的 K/V。

为什么需要 decoupled RoPE？RoPE 在 \(q\) 和 \(k\) 上乘一个依赖位置的旋转矩阵 \(R_m\)：\(q^\top R_{m}^\top R_{n} W^{UK}c\)。中间夹着依赖相对位置的 \(R_{n-m}\)，\(W^{UK}\) 就无法再被吸收进固定的 query 投影。DeepSeek 的解法：额外用一个小维度 \(d_h^R\) 的 query/key 分量专门承载 RoPE，key 部分 \(k_t^R=\mathrm{RoPE}(W^{KR}h_t)\) 所有头共享并单独缓存；最终 \(q=[q^C;q^R]\)，\(k=[k^C;k^R]\)。

缓存大小。每 token 每层缓存 \(d_c+d_h^R\) 个元素。DeepSeek-V2/V3 用 \(d_c=512\)（\(=4d_h\)），\(d_h^R=64\)（\(=d_h/2\)），即 576 个元素；论文称这相当于只有 2.25 组的 GQA，但效果报告强于 MHA。对比 MHA 的 \(2Hd_h\)（V2 中 \(H=128,d_h=128\) 时是 32768 个元素）。

DeepSeek-V2 也对 query 做了低秩压缩（\(c^Q\)），主要是为了减少训练时激活显存，与 KV cache 无关。

常见误区MLA 不是"K/V 共享头"——每个头仍有自己的上投影得到的 K/V，只是它们都由同一个低秩潜在向量生成（低秩分解），表达能力比 GQA 强。另外"不能直接加 RoPE"是面试必问的点。
Say it in English

MLA compresses keys and values into a shared low-rank latent, around five hundred dimensions per token, and only that latent is cached. Per-head keys and values are up-projections of the latent, and because attention scores are bilinear, the key up-projection can be absorbed into the query side and the value up-projection into the output projection, so you never materialize full keys at inference. RoPE breaks that absorption because a position-dependent rotation sits between the query and the key up-projection, so DeepSeek adds a small decoupled RoPE key shared across heads. The cache ends up comparable to GQA with very few groups, while quality is reported to match or beat MHA.

    思路

Sliding window attention 与 attention sinks

一句话

滑动窗口只看最近 \(W\) 个 token，复杂度 \(O(TW)\)、KV cache 固定为 \(W\)；堆叠 \(L\) 层后感受野约 \(L\cdot W\)。Attention sink 指模型把大量注意力倒在前几个 token 上，流式推理时必须保留它们。

Sliding-window attention bounds compute and cache by a window size while stacking layers grows the receptive field; attention sinks are initial tokens that soak up attention mass and must be kept when evicting the cache.

Sliding window（SWA）。mask 改为 \(i-W< j\le i\)。Mistral 7B 用 \(W=4096\)，配合 rolling buffer KV cache（环形缓冲区，大小恒为 \(W\)）。信息可以逐层向前传递，\(L\) 层后理论感受野 \(\approx L\times W\)。很多模型采用局部/全局交替：例如 Gemma 2 每隔一层用 4096 窗口的局部注意力，Gemma 3 改为 5 层局部（窗口 1024）配 1 层全局，以压缩长上下文 KV cache。

Attention sinks。StreamingLLM（Xiao et al. 2023）发现：即便语义无关，很多头会把大量注意力分给序列开头的几个 token。解释：softmax 要求权重和为 1，当一个头"不想读任何东西"时需要一个垃圾桶，而开头 token 对所有位置都可见，于是被学成了 sink。后果：纯滑动窗口在把开头 token 驱逐出 cache 后困惑度暴涨。解决：永远保留前 4 个 token 的 KV + 最近窗口，可以流式生成很长的文本（注意：这并不让模型"记住"窗口外的内容）。论文还提出预训练时加一个专门的可学习 sink token。

相关设计：在 softmax 分母里加一个可学习的"空选项"（相当于每个头一个 learned sink logit），让头可以把注意力"投给无"，OpenAI 的 gpt-oss 模型卡描述了每个头在 softmax 分母里有一个可学习 bias（让头可以"什么都不看"），层间交替使用 128 token 的带状窗口注意力和全注意力，并用 GQA（64 个 query 头共享 8 个 KV 头）。

Say it in English

Sliding-window attention restricts each token to the last W tokens, so compute is linear in sequence length and the KV cache is bounded by the window; stacking layers still propagates information further, roughly L times W. Many models interleave local and global layers to get most of the memory savings while keeping some full attention. Attention sinks are the observation that many heads dump attention onto the first few tokens, because softmax weights must sum to one and those tokens are visible to everyone. If you evict them in a streaming setting, perplexity blows up, so StreamingLLM keeps the first few tokens plus a recent window.

§3 · POSITIONAL ENCODING位置编码

RoPE 是这一节的重中之重：几乎所有现代开源 LLM 都用它，面试官常要求现场推导"为什么 RoPE 只依赖相对位置"，再追问长上下文外推（PI / NTK / YaRN）。

★

为什么需要位置编码；绝对 vs 相对

一句话

Attention 对 key 的顺序是置换不变的，"dog bites man" 与 "man bites dog" 在没有位置信息时看起来一样；位置编码可以加到输入上（绝对），也可以直接注入注意力分数（相对）。

Attention by itself is order-agnostic, so we inject position either by adding absolute position vectors to the input or by making attention scores depend on relative offsets.

为什么相对位置更好？语言规律大多是平移不变的（"形容词在名词前一个位置"不依赖于句子在文档的哪里）。相对编码天然共享这种统计，并且对训练长度外的位置更有机会泛化。

Say it in English

Self-attention is permutation-equivariant, so without positional information the model can't distinguish word orders. The original Transformer added fixed sinusoidal vectors to the input, BERT and GPT-2 used learned absolute embeddings, and later work moved position into the attention score itself, which makes it relative: T5 adds a learned bias per relative distance bucket, ALiBi adds a linear distance penalty, and RoPE rotates queries and keys so their dot product depends only on the offset. Relative schemes match the translation-invariant structure of language and extrapolate better.

☆

Sinusoidal、learned、T5 bias

一句话

Sinusoidal：\(PE_{(p,2i)}=\sin(p/10000^{2i/d})\)，\(PE_{(p,2i+1)}=\cos(\cdot)\)，频率几何递减；\(PE_{p+k}\) 是 \(PE_p\) 的线性函数（旋转），这是 RoPE 的思想源头。

Sinusoidal encodings use geometrically spaced frequencies, and shifting position is a rotation of each sine-cosine pair, which is exactly the idea RoPE later moves into the attention dot product.

Sinusoidal 的性质。第 \(i\) 对维度的角频率 \(\omega_i=10000^{-2i/d}\)，波长从 \(2\pi\) 到 \(2\pi\cdot 10000\)。由和角公式

$$\begin{pmatrix}\sin\omega(p+k)\\ \cos\omega(p+k)\end{pmatrix}=\begin{pmatrix}\cos\omega k & \sin\omega k\\ -\sin\omega k & \cos\omega k\end{pmatrix}\begin{pmatrix}\sin\omega p\\ \cos\omega p\end{pmatrix}$$

偏移 \(k\) 对应一个只依赖 \(k\) 的旋转，所以模型"有可能"学到相对位置。但它是加在 embedding 上的，经过 \(W_Q,W_K\) 后点积里混入了内容-位置交叉项，相对性并不干净。

Learned absolute：一个 \((T_{\max},d)\) 的可学习表，简单有效，但超过 \(T_{\max}\) 直接没有定义。

T5 relative bias：每个头对每个相对距离"桶"学一个标量，加在 logit 上：\(S_{ij}=q_i\cdot k_j+b_{h}(\text{bucket}(i-j))\)。近距离精确分桶、远距离对数分桶。缺点：需要额外的 bias 矩阵加到 attention 上，和 FlashAttention 等融合 kernel 配合稍麻烦。

Say it in English

Sinusoidal encodings assign each pair of dimensions a frequency, decreasing geometrically from one to one over ten thousand. Shifting position by k rotates each sine-cosine pair by an angle proportional to k, so relative offsets are linear functions of the encoding. But because the encoding is added to the input and then passes through projections, the attention score mixes content and position terms. RoPE takes the rotation idea and applies it directly to queries and keys.

★

RoPE：完整推导

一句话

把 \(q,k\) 的维度两两配对视为复数，位置 \(m\) 处乘以 \(e^{im\theta_i}\)（旋转角 \(m\theta_i\)），则 \(\langle R_mq,R_nk\rangle=\langle q,R_{n-m}k\rangle\)，点积只依赖相对位置 \(n-m\)；\(\theta_i=\text{base}^{-2i/d_h}\)，base 通常 10000。

RoPE rotates each two-dimensional slice of the query and key by an angle proportional to position, so their dot product depends only on the relative offset.

出自 RoFormer（Su et al. 2021）。

1. 二维情形

设 \(q,k\in\mathbb{R}^2\)，定义旋转矩阵 \(R(\alpha)=\begin{pmatrix}\cos\alpha&-\sin\alpha\\ \sin\alpha&\cos\alpha\end{pmatrix}\)。位置 \(m\) 的 query 变成 \(R(m\theta)q\)，位置 \(n\) 的 key 变成 \(R(n\theta)k\)。点积：

$$\big(R(m\theta)q\big)^\top R(n\theta)k=q^\top R(m\theta)^\top R(n\theta)k=q^\top R(-m\theta)R(n\theta)k=q^\top R\big((n-m)\theta\big)k$$

用到两个事实：旋转矩阵正交，\(R(\alpha)^\top=R(-\alpha)\)；旋转可合成，\(R(\alpha)R(\beta)=R(\alpha+\beta)\)。结果只依赖 \(n-m\)。

2. 复数形式（更简洁）

把 \(q=(q_1,q_2)\) 看成 \(\tilde q=q_1+iq_2\)。旋转就是乘 \(e^{im\theta}\)。二维实向量点积 \(=\mathrm{Re}(\tilde q\,\overline{\tilde k})\)。于是

$$\mathrm{Re}\Big[(\tilde q e^{im\theta})\overline{(\tilde k e^{in\theta})}\Big]=\mathrm{Re}\Big[\tilde q\,\overline{\tilde k}\,e^{i(m-n)\theta}\Big]$$

同样只依赖 \(m-n\)。

3. 推广到 \(d_h\) 维

把 \(d_h\) 维分成 \(d_h/2\) 对，第 \(i\) 对用频率 \(\theta_i=\text{base}^{-2i/d_h}\)（\(i=0,\dots,d_h/2-1\)）。整体旋转是块对角矩阵 \(R_m=\mathrm{diag}(R(m\theta_0),\dots,R(m\theta_{d_h/2-1}))\)。点积是各对点积之和，每一项都只依赖 \(n-m\)，所以

$$\langle R_mq,R_nk\rangle=q^\top R_{n-m}k=\sum_{i}\mathrm{Re}\big[\tilde q_i\overline{\tilde k_i}e^{i(m-n)\theta_i}\big]$$

4. 性质

  • 保范数：旋转正交，\(\|R_mq\|=\|q\|\)，不改变 logit 的尺度（不像加性编码）。
  • 只作用于 q、k，不作用于 v：位置只影响"看哪里"，不污染被搬运的内容。
  • 多尺度：高频对（\(i\) 小，\(\theta_i\approx1\)）对相邻位置敏感，编码局部顺序；低频对（\(\theta_i\approx 1/\text{base}\)）在训练长度内几乎不转一圈，编码长程/粗位置，也常被用作"语义通道"。
  • 远程衰减：论文证明在某些假设下 \(|q^\top R_{n-m}k|\) 的上界随 \(|n-m|\) 增大而衰减（这是一个上界性质，不是保证）。
  • 相对性对 KV cache 友好：缓存的 key 已经旋转好了，新 token 的 query 只需用自己的位置旋转。

5. 两种实现布局

Interleaved（原论文 / Meta 原版 LLaMA）：配对 \((x_0,x_1),(x_2,x_3),\dots\)，用 view_as_complex 实现。Half-split / rotate_half（HF transformers、GPT-NeoX）：配对 \((x_i,x_{i+d_h/2})\)：

$$\mathrm{RoPE}(x)=x\odot\cos(m\theta)+\mathrm{rotate\_half}(x)\odot\sin(m\theta),\quad \mathrm{rotate\_half}([x_1;x_2])=[-x_2;x_1]$$

其中 \(\cos(m\theta)\) 向量是 \([\cos m\theta_0,\dots,\cos m\theta_{d_h/2-1},\cos m\theta_0,\dots]\)（拼两遍）。验证第 \(i\) 对：新 \(x_i=x_i\cos-x_{i+d/2}\sin\)，新 \(x_{i+d/2}=x_{i+d/2}\cos+x_i\sin\)，正是二维旋转。两种布局只相差一个固定的维度置换，数学上等价，但权重不能混用（HF 转换 LLaMA 权重时会对 \(W_Q,W_K\) 的行做置换）。§11 的代码数值验证了这一点。

qv, kv = rng.standard_normal(dh), rng.standard_normal(dh)
Q = apply_rope(np.tile(qv, (T, 1)), cos, sin)   # same content q at every position

常见误区
  • 把 RoPE 加到 v 上，或加到 attention 输出上——错，只旋转 q 和 k。
  • 在 GQA 中 repeat K 之后再做 RoPE——不会错但浪费；应在 repeat 前对 \(H_{kv}\) 个头做。
  • KV cache 解码时用错位置：新 token 的位置是 cache 长度（\(t\)），不是 0。
  • bf16 下算角度 \(m\theta_i\)：\(m\) 很大时 bf16 精度不够（8 位尾数），角度要在 fp32 里算。
Say it in English

RoPE splits the query and key into two-dimensional pairs and rotates each pair by an angle equal to the position times a frequency, with frequencies decaying geometrically from one to one over the base, usually ten thousand. Because rotations are orthogonal and compose additively, the rotated query at position m dotted with the rotated key at position n equals q transpose R of n minus m times k. So the attention logit depends only on the relative offset, while the norms are preserved and values are left untouched. In complex form it is just multiplying each pair by e to the i m theta. High-frequency pairs capture local order and low-frequency pairs capture long-range position.

追问链
  1. Why does RoPE fail to extrapolate beyond the training length?
    思路
    低频维度在训练长度 \(L\) 内转不满一圈（波长 \(\lambda_i=2\pi/\theta_i>L\)），超过 \(L\) 后出现训练时从未见过的旋转角，分数分布异常（out-of-distribution）。高频维度已经转过很多圈，见过所有角度，不是问题。所以扩展方法都针对低频维度做文章。
  2. What does increasing the RoPE base do?
    思路
    所有 \(\theta_i\) 变小（尤其低频端），同样的位置差对应更小的角度，波长变长，能覆盖更长上下文。LLaMA-3 用 base 500000；长上下文继续训练时常把 base 调大（"ABF, adjusted base frequency"）。NTK-aware 插值本质上就是改 base。
  3. Is RoPE purely relative in practice?
    思路
    分数只依赖 \(n-m\)，是。但 causal mask 和 attention sink 等让模型仍能感知绝对位置（比如第一个 token 很特殊）。

RoPE 外推：PI、NTK-aware、YaRN；ALiBi；NoPE

一句话

PI 把位置线性压缩回训练范围（所有频率统一除以 \(s\)）；NTK-aware 改 base，高频几乎不动、低频被插值；YaRN 按频率分段（高频不动、低频插值、中间过渡）再加注意力温度修正，只需少量微调即可扩展多倍。

Position interpolation squeezes positions uniformly, NTK-aware scaling changes the base so high frequencies stay intact, and YaRN interpolates only the low-frequency dimensions plus a temperature correction.

设训练长度 \(L\)，目标长度 \(L'\)，扩展倍数 \(s=L'/L\)。

  1. Position Interpolation（PI，Chen et al. 2023）：把位置 \(m\) 换成 \(m/s\)，等价于所有 \(\theta_i\to\theta_i/s\)。所有旋转角都落在训练见过的范围里，再微调约 1000 步。缺点：高频维度也被压缩了 \(s\) 倍，相邻 token 的角度差变小，局部分辨率下降。
  2. NTK-aware（社区提出，后在 YaRN 论文中整理）：改 base 为 \(b'=b\cdot s^{d_h/(d_h-2)}\)。效果：最高频 \(\theta_0=1\) 不变，最低频恰好被除以 \(s\)，中间平滑过渡。不微调也能有一定效果。
  3. YaRN（Peng et al. 2023）：
    • "NTK-by-parts"：对每一维计算它在训练长度内转的圈数 \(r=L/\lambda_i\)。\(r<\alpha\)（低频，转不满）：完全插值（\(\theta/s\)）；\(r>\beta\)（高频）：不动；中间线性 ramp。LLaMA 推荐 \(\alpha=1,\beta=32\)。
    • 注意力温度：logit 除以 \(t\)，推荐 \(\sqrt{1/t}=0.1\ln s+1\)，实现上把 q、k 各乘 \(\sqrt{1/t}\)，零开销。原因：插值后注意力分布熵会变化，需要校正。
    • 论文报告相比之前方法所需微调 token 少约 10 倍、步数少约 2.5 倍。gpt-oss、Qwen、DeepSeek 等都用过 YaRN 扩展上下文。
  4. ALiBi（Press et al. 2021）：不用任何位置 embedding，直接给 logit 加 \(-m_h\cdot(i-j)\)，每头斜率 \(m_h\) 取几何序列（如 8 头时 \(1/2,1/4,\dots,1/256\)）。"Train short, test long"：短训练长外推的困惑度表现好，但本质是强制近因偏置，长程检索能力有限。
  5. NoPE：decoder-only + causal mask 不加任何位置编码也能训练，因为 causal mask 本身泄漏了位置（例如可以通过"有多少 token 可见"来计数）。有研究报告其长度泛化不差（Kazemnejad et al. 2023），但大规模 LLM 很少纯 NoPE；也有模型在部分层用 NoPE、部分层用 RoPE 混合。
常见误区以为改了 RoPE 缩放就"支持"长上下文了。位置外推只是必要条件；真正的长上下文能力还要长文档数据继续训练、评测（needle-in-a-haystack 远远不够，见 RULER 等），以及 KV cache 显存（见 05、08）。
Say it in English

RoPE breaks beyond the training length because the low-frequency dimensions encounter rotation angles they never saw in training. Position interpolation divides all positions by the extension factor, so every angle stays in range, but it also compresses the high frequencies and blurs local order. NTK-aware scaling instead changes the base, leaving the highest frequency unchanged and fully interpolating the lowest. YaRN refines this per dimension: frequencies that complete many rotations within the training context are left alone, ones that don't complete a full rotation are interpolated, with a linear ramp in between, plus a small attention temperature correction. With a short fine-tune it extends context several-fold.

  1. Derive why NTK-aware base change leaves θ_0 unchanged and divides the lowest frequency by s.
    思路
    \(\theta_i'=b'^{-2i/d}=b^{-2i/d}\cdot s^{-\frac{2i}{d}\cdot\frac{d}{d-2}}=\theta_i\cdot s^{-2i/(d-2)}\)。\(i=0\)：因子 \(s^0=1\)，不变。最低频 \(i=d/2-1\)：指数 \(-\frac{2(d/2-1)}{d-2}=-1\)，因子 \(1/s\)，恰好等价于 PI。

Pre-Norm vs Post-Norm：梯度论证

一句话

Post-Norm \(x_{l+1}=\mathrm{LN}(x_l+F(x_l))\) 把 LN 放在残差主路上，梯度每层都要穿过 LN 的 Jacobian，深层时初始化附近梯度不稳、需要 warmup；Pre-Norm \(x_{l+1}=x_l+F(\mathrm{LN}(x_l))\) 留下一条恒等的"梯度高速公路"，训练稳定，但最终效果有时略差（表征坍缩到残差主路）。

Pre-norm keeps an identity path through the residual stream so gradients flow cleanly and training is stable without long warmup; post-norm can reach slightly better quality but is hard to train deep.

梯度论证。Pre-Norm 展开：\(x_L=x_0+\sum_{l=0}^{L-1}F_l(\mathrm{LN}(x_l))\)，所以

$$\frac{\partial \mathcal{L}}{\partial x_l}=\frac{\partial \mathcal{L}}{\partial x_L}\Big(I+\sum_{k\ge l}\frac{\partial F_k(\mathrm{LN}(x_k))}{\partial x_l}\Big)$$

其中的恒等项 \(I\) 保证了任意浅层都能直接收到顶层的梯度，不经过任何乘性衰减。Post-Norm 中：\(\partial x_{l+1}/\partial x_l=J_{\mathrm{LN}}\,(I+\partial F/\partial x_l)\)，梯度是 \(L\) 个这样的矩阵连乘，LN 的 Jacobian 会按输入范数缩放梯度，无恒等通路。Xiong et al. 2020（On Layer Normalization in the Transformer Architecture）证明初始化时 Post-Norm 靠近输出层的参数梯度期望很大，因此必须用 learning-rate warmup；Pre-Norm 梯度表现良好，可以去掉 warmup 或缩短。

Pre-Norm 的缺点。残差流 \(x_l\) 的范数随层数增长（每层都往上加东西，而主路从不被归一化），深层的 \(F_l\) 输出相对于主路越来越小，使得后面的层贡献减弱、"有效深度"变浅。这是 Post-Norm 调好时最终效果可能更好的一个解释。另外必须在最后加一个 final norm，否则输出尺度失控。

折中方案。

  • DeepNorm（DeepNet, Wang et al. 2022）：Post-Norm 但残差放大 \(x_{l+1}=\mathrm{LN}(\alpha x_l+F(x_l))\)，\(\alpha>1\)，并按深度缩小初始化，训练到 1000 层。
  • Sandwich norm：子层输入和输出都加 norm，即 \(x+\mathrm{Norm}(F(\mathrm{Norm}(x)))\)，Gemma 2/3 采用（pre- 与 post-norm 并用）。
  • OLMo 2 把 norm 放到子层输出端（\(x+\mathrm{Norm}(F(x))\)）并配合 QK-norm 以提升稳定性。
常见误区Pre-Norm 是 x + F(norm(x))，不是 norm(x + F(x))，也不是 norm(x) + F(norm(x))（后者会把归一化后的值写入残差主路，破坏恒等通路）。
Say it in English

In post-norm, the layer norm sits on the residual path, so the gradient to early layers is a product of L Jacobians that each pass through a norm, and at initialization the gradients near the output are large, which is why post-norm needs careful warmup. In pre-norm, we normalize only the input to each sublayer, so the residual stream is a sum, and the gradient with respect to any layer contains an identity term straight from the top. That makes deep models train stably. The downside is that the residual norm grows with depth, so later layers contribute relatively less, and you need a final norm before the output head.

LayerNorm vs RMSNorm

一句话

LayerNorm 减均值、除标准差、再仿射（\(\gamma,\beta\)）；RMSNorm 只除以均方根 \(\sqrt{\mathrm{mean}(x^2)+\epsilon}\) 再乘 \(\gamma\)，省掉均值计算和 bias，速度更快、效果相当。

RMSNorm drops the mean-centering and bias of LayerNorm and just rescales by the root mean square, which is cheaper and works as well in practice.

$$\mathrm{LN}(x)=\gamma\odot\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}+\beta,\qquad \mathrm{RMSNorm}(x)=\gamma\odot\frac{x}{\sqrt{\frac1d\sum_i x_i^2+\epsilon}}$$

RMSNorm（Zhang & Sennrich 2019）的假设：LayerNorm 的成功主要来自尺度不变性（re-scaling invariance），而不是平移不变性（re-centering）。去掉均值后少一次规约、少一个参数向量，在 GPU 上是 memory-bound 操作，省一次读写就有实际收益。

为什么 Transformer 用 LN 不用 BN？BN 依赖 batch 统计量，对变长序列、padding、小 batch、自回归推理（batch=1，逐 token）都很别扭，训练/推理行为不一致；LN/RMSNorm 对每个 token 独立归一化，与 batch 和序列长度无关。

数值注意。bf16 下求平方均值会损失精度，实现里先 .float() 计算再转回；\(\epsilon\) 常取 1e-5 或 1e-6（见 §10）。

Say it in English

LayerNorm subtracts the mean, divides by the standard deviation, and applies a learned scale and shift. RMSNorm skips the mean subtraction and the shift: it divides by the root mean square and multiplies by a learned gain. The argument is that the useful property is scale invariance, not re-centering. Since normalization is memory-bound, dropping a reduction and a parameter vector gives a real speedup, and empirically quality is the same. We use per-token normalization rather than batch norm because batch statistics don't make sense for variable-length sequences or one-token-at-a-time decoding.

★

FFN：4× 扩展、SwiGLU 与 8/3

一句话

标准 FFN \(W_2\,\sigma(W_1x)\)，中间维度 \(4d\)，参数 \(8d^2\)；SwiGLU \(W_2(\mathrm{SiLU}(W_1x)\odot W_3x)\) 有三个矩阵，中间维度取 \(\frac{8}{3}d\) 使参数仍为 \(3\cdot d\cdot\frac83 d=8d^2\)。

The MLP expands to 4d and back; SwiGLU adds a gating matrix, so its hidden size is set to about eight-thirds d to keep the parameter count at eight d squared.

FFN 的作用。逐位置的两层 MLP，占每层约 2/3 参数（MHA 下 \(4d^2\) vs \(8d^2\)）。attention 负责"在 token 间搬运信息"，FFN 负责"在每个 token 内做非线性变换/查知识"。

GLU 家族（Shazeer 2020, GLU Variants Improve Transformer）：

$$\mathrm{FFN}_{\text{SwiGLU}}(x)=W_2\big(\mathrm{SiLU}(W_1x)\odot W_3x\big),\qquad \mathrm{SiLU}(z)=z\,\sigma(z)$$

一个分支做"门"（经过非线性），另一个分支是线性"值"，逐元素相乘。门控让网络可以乘性地选择特征，表达能力更强；论文在相同参数/计算下发现 SwiGLU、GeGLU 困惑度最好。

8/3 的来源。保持参数量 \(=8d^2\)：\(3\cdot d\cdot d_{ff}=8d^2\Rightarrow d_{ff}=\frac83 d\)。LLaMA 实际做法：\(d_{ff}=\text{round\_up}(\frac{2}{3}\cdot 4d,\ 256)\)。对 \(d=4096\)：\(\frac83\cdot4096=10922.67\to 11008\)（256 的倍数，硬件友好）。这就是 LLaMA-7B 的 11008。

FFN 作为 key-value 记忆（Geva et al. 2021）：把 \(W_1\) 的每一行看成一个 "key"，\(W_2\) 的每一列看成对应的 "value"。\(\mathrm{FFN}(x)=\sum_i \sigma(k_i\cdot x)\,v_i\)：输入与 key 匹配的程度决定对应 value 被写入残差流的量。他们发现浅层 key 匹配表层模式（n-gram），深层 key 匹配语义模式，value 倾向于提升匹配后下一个 token 的概率。这和 attention 很像，只是 "keys" 是固定参数而非上下文 token，softmax 换成了逐元素非线性（不归一化）。ROME 等知识编辑方法就基于"事实存储在中层 FFN"这一观点。

常见误区SwiGLU 参数计数时忘记第三个矩阵；或者以为 SwiGLU 中间维度也是 \(4d\)（那样参数会变成 \(12d^2\)）。另外 PaLM 用了 SwiGLU 但没有缩小中间维度（\(4d\)），所以它的 FFN 更大——问到具体模型时要谨慎。
Say it in English

The MLP is applied to each token independently and holds most of the parameters. The classic version projects up to four d, applies a nonlinearity and projects back, which is eight d squared parameters. SwiGLU replaces it with a gated unit: one projection goes through SiLU and multiplies elementwise with a second linear projection, and then a third matrix projects down. Since there are three matrices, the hidden size is set to two-thirds of four d, about eight-thirds d, rounded to a hardware-friendly multiple, which is how LLaMA-7B gets 11008. Gating gives consistently better perplexity at the same parameter count. A useful interpretation is that the MLP is a key-value memory: rows of the first matrix detect patterns and columns of the second write associated outputs.

    思路

Residual stream 视角

一句话

把残差连接看成一条贯穿所有层的"总线"：每个 attention 头和 FFN 从中读（经过 norm + 线性投影），把结果加回去；最终的 logits 是所有组件贡献的线性叠加（除去 norm 的缩放）。

The residual stream is a shared communication channel: every head and MLP reads from it through a projection and writes its output back additively.

\(x_L=x_0+\sum_l \mathrm{Attn}_l(\cdot)+\sum_l\mathrm{FFN}_l(\cdot)\)。因为是相加，可以把输出分解为每个组件的贡献（direct logit attribution），可以在中间层直接乘 unembedding 看模型"当前预测"（logit lens）。不同组件在残差流的不同（近似正交的）子空间里通信。这是 mechanistic interpretability 的基础框架（Elhage et al. 2021, A Mathematical Framework for Transformer Circuits），详见 11。

工程意义：残差流维度 \(d\) 是信息带宽瓶颈；深层模型的残差范数增长、massive activations / outlier features（个别维度数值极大）都在残差流中出现，影响量化与稳定性。

Say it in English

I think of the residual stream as a shared bus that runs through the whole network. Each attention head and each MLP reads from it through a norm and a linear projection, and adds its output back. Because everything is additive, the final logits decompose into contributions from individual components, which is what interpretability tools like the logit lens and direct logit attribution exploit. It also means the model dimension acts as the bandwidth of that channel.

☆

Tied embeddings、final norm、LM head、并行 attn+FFN

一句话

输入 embedding \(E\in\mathbb{R}^{V\times d}\) 和输出 unembedding 可以共享（\(\text{logits}=hE^\top\)），省 \(Vd\) 参数，小模型收益大；并行块 \(x+\mathrm{Attn}(\mathrm{LN}(x))+\mathrm{FFN}(\mathrm{LN}(x))\) 让两个子层可以融合矩阵乘、提速约 15%。

Weight tying shares the input embedding with the output projection, saving V times d parameters; parallel blocks compute attention and MLP from the same normalized input to fuse matmuls.

Weight tying（Press & Wolf 2017）：直觉是"输入时 token 的表示"和"输出时预测该 token 的方向"应该相似。GPT-2、T5（部分版本）、Gemma 共享；LLaMA 不共享。对 \(V=256\text{k}\)、\(d=2048\) 的小模型，embedding 占 5 亿参数，共享节省很多；大模型中占比小，不共享更灵活。共享时注意：embedding 的梯度来自两个地方；某些实现会把输入 embedding 乘 \(\sqrt d\)（原始 Transformer、Gemma）以匹配尺度。

Final norm：Pre-Norm 架构中残差流从未被归一化，LM head 前必须再加一个 norm。

并行 attention + FFN（GPT-J 首创，PaLM 采用）：\(y=x+\mathrm{Attn}(\mathrm{LN}(x))+\mathrm{MLP}(\mathrm{LN}(x))\)。两个子层的输入投影可以合并成一个大矩阵乘法，PaLM 报告大规模下训练快约 15%，小模型有轻微质量下降、62B 规模下可忽略。代价：FFN 看不到同层 attention 的输出。

Say it in English

Weight tying uses the same matrix for the input embedding and the output projection, so logits are the hidden state dotted with every token embedding. It saves V times d parameters, which matters for small models with big vocabularies, and acts as a mild regularizer; many large models untie them for flexibility. In a pre-norm model you also need a final norm before the head. Parallel blocks, used in GPT-J and PaLM, feed the same normalized input to attention and the MLP and sum both outputs, which lets you fuse the input matmuls and gives around fifteen percent speedup at scale.

参数量：≈ 12Ld² + Vd 的推导

一句话

每层 attention \(4d^2\) + FFN（4×）\(8d^2\) = \(12d^2\)，\(L\) 层共 \(12Ld^2\)，再加 embedding \(Vd\)（不共享时再加 \(Vd\)）；norm 和 bias 可忽略。

Each layer has four d squared attention parameters and eight d squared MLP parameters, so about twelve L d squared in total, plus V times d for embeddings.

逐项推导（无 bias、MHA、标准 4× FFN）

  • Attention：\(W_Q,W_K,W_V,W_O\in\mathbb{R}^{d\times d}\) → \(4d^2\)
  • FFN：\(W_1\in\mathbb{R}^{d\times 4d}\)，\(W_2\in\mathbb{R}^{4d\times d}\) → \(8d^2\)
  • 2 个 norm：\(2d\)（RMSNorm）或 \(4d\)（LN 含 bias）→ 可忽略
  • 每层 \(\approx12d^2\)；全模型 \(N\approx 12Ld^2+Vd\,(+Vd\text{ 若不共享})\)

变体

  • SwiGLU：\(3\cdot d\cdot d_{ff}\)，取 \(d_{ff}=\frac83 d\) 时仍是 \(8d^2\)。
  • GQA：\(W_K,W_V\) 变成 \(d\times H_{kv}d_h\)，attention 参数 \(=2d^2+2d\cdot H_{kv}d_h=2d^2(1+H_{kv}/H)\)。
  • MoE：FFN 部分 ×\(E\)（总参数），激活参数只 ×\(k\)。

def count_params(d, L, V, d_ff, n_heads, n_kv_heads=None, gated=True, tied=False, norm="rms"):
    """Decoder-only LLaMA-style param count (no biases)."""
    n_kv_heads = n_kv_heads or n_heads
    dh = d // n_heads
    attn = d * d + 2 * d * (n_kv_heads * dh) + d * d      # Wq, Wk, Wv, Wo
    mlp = (3 if gated else 2) * d * d_ff                  # SwiGLU: W1, W3, W2
    norms = 2 * d * (1 if norm == "rms" else 2)           # 2 norms per block (LN has bias)
    per_layer = attn + mlp + norms
    emb = V * d
    head = 0 if tied else V * d
    final_norm = d * (1 if norm == "rms" else 2)
    total = L * per_layer + emb + head + final_norm
    return dict(attn=attn, mlp=mlp, per_layer=per_layer, emb=emb, total=total)

def train_flops(N, D):          # forward 2ND + backward 4ND
    return 6 * N * D

def attn_flops_per_token(L, d, ctx):   # QK^T and AV, forward, per token
    return 2 * 2 * L * ctx * d          # = 4 * L * ctx * d  (Kaplan uses 2*L*ctx*d for one mult-add convention)

def kv_cache_bytes(L, n_kv_heads, dh, seq, batch=1, bytes_per=2):
    return 2 * L * n_kv_heads * dh * seq * batch * bytes_per

Say it in English

Each layer has four d squared parameters in attention, for the query, key, value and output projections, and eight d squared in the MLP, with up and down projections to four d. So it's about twelve d squared per layer, twelve L d squared in total, plus V times d for the embedding and another V times d if the head is untied. For LLaMA-2-7B, with d equal to 4096 and 32 layers, twelve L d squared is 6.4 billion, plus about a quarter billion for embeddings, which gives 6.7 billion. SwiGLU keeps the same count by using an eight-thirds hidden size, and GQA shrinks the key and value matrices.

★

训练 FLOPs ≈ 6ND；推理 ≈ 2N / token

一句话

每个参数每个 token：前向 1 次乘加 = 2 FLOPs；反向要算对激活的梯度和对权重的梯度，各 2 FLOPs，共 4；合计 6。所以训练 \(C\approx6ND\)，推理前向 \(\approx2N\) FLOPs/token（不计 attention 的 \(T\) 相关项）。

Training costs about six N D FLOPs: two for the forward multiply-add per parameter per token, and four for the backward pass, which computes gradients with respect to both activations and weights.

推导

考虑一个线性层 \(Y=XW\)，\(X\in\mathbb{R}^{D\times m}\)（\(D\) 个 token），\(W\in\mathbb{R}^{m\times n}\)，参数 \(mn\)。

  • 前向：\(XW\) 需要 \(D\cdot m\cdot n\) 次乘加 = \(2Dmn\) FLOPs → 每参数每 token 2。
  • 反向-对输入：\(\partial\mathcal L/\partial X=(\partial\mathcal L/\partial Y)W^\top\)，同样 \(2Dmn\)（为了继续往前传）。
  • 反向-对权重：\(\partial\mathcal L/\partial W=X^\top(\partial\mathcal L/\partial Y)\)，同样 \(2Dmn\)。
  • 合计 \(6Dmn\)，对所有矩阵求和得 \(6ND\)。

Embedding 查表不是矩阵乘（几乎 0 FLOPs），所以严格来说 \(N\) 应该取非 embedding 参数加上 LM head（LM head 是真矩阵乘）。Kaplan 等用非 embedding 参数 \(N\)。

Attention 项

每 token 每层，\(QK^\top\) 和 \(AV\) 前向各 \(2\cdot T_{\text{ctx}}\cdot d\) FLOPs（因果时平均可减半）。前向每 token 共 \(\approx 4Ld\,T_{\text{ctx}}\)，与 \(2N\approx 24Ld^2\) 相比比值 \(\approx T_{\text{ctx}}/(6d)\)。\(T=4096,d=4096\) 时约 16%，长上下文训练时不能忽略（Kaplan et al. 2020 写作 \(C_{\text{fwd}}\approx 2N+2n_{\text{layer}}n_{\text{ctx}}d_{\text{attn}}\)，attention 项系数与这里差 2 倍，来自是否把 \(AV\) 单列、是否按因果平均等约定差异；面试时说清楚自己的约定即可）。

训练时间估算（白板模板）

LLaMA-2-7B，\(D=2\text{T}\)：\(C=6\times6.7\times10^9\times2\times10^{12}\approx8\times10^{22}\)。假设 H100 bf16 稠密峰值约 \(10^{15}\) FLOP/s（约 989 TFLOPs），MFU 40%：每卡 \(4\times10^{14}\)。1000 张卡：\(4\times10^{17}\) FLOP/s → \(8\times10^{22}/4\times10^{17}=2\times10^5\) 秒 \(\approx\) 2.3 天。（数量级估算，峰值数字取整。）

推理

每生成一个 token \(\approx 2N\) FLOPs + attention 项 \(\approx 4Ld\cdot t\)。7B 模型 ≈ 14 GFLOPs/token。但 batch=1 解码是带宽瓶颈：每步要读全部 14 GB 权重（bf16），H100 HBM 约 3.35 TB/s → 上限约 240 tokens/s。详见 08。

"backward = 2× forward" 何时不成立？开启 activation checkpointing 时要额外重算一次前向，变成约 \(8ND\)（硬件 FLOPs，HFU）；MFU 的分子仍按 \(6ND\) 计算。

常见误区
  • 说 "\(3ND\)" 或 "\(2ND\)"——忘了乘加算 2 FLOPs 或忘了反向两份。
  • 把 \(D\) 理解为数据集大小（样本数）——是 token 数。
  • 对 MoE 用总参数 \(N\)——应该用激活参数。
Say it in English

For every parameter and every token, the forward pass does one multiply-add, which is two FLOPs. The backward pass does two matmuls of the same size: one for the gradient with respect to the input, to keep backpropagating, and one for the gradient with respect to the weight. That's four more FLOPs, so six in total, giving six N D for training. Inference is just the forward pass, about two N FLOPs per token. On top of that, attention adds a term proportional to layers times d times context length, which is small relative to six N D unless the context is several times the model width. As a sanity check, a 7B model on two trillion tokens is about eight times ten to the twenty-two FLOPs.

§6 · ENCODER / DECODEREncoder-only、Decoder-only、Encoder-Decoder

高频的"讨论题"：为什么今天的大模型几乎都是 decoder-only？没有唯一正确答案，要把论点讲清楚，并承认这在一定程度上是经验和工程选择。

☆

BERT / GPT / T5 / Prefix LM 与 decoder-only 为何主导

一句话

Encoder-only（BERT）双向注意力 + MLM，擅长理解/表征；decoder-only（GPT）因果注意力 + 下一个 token 预测，天然能生成；encoder-decoder（T5）编码器双向、解码器因果 + cross-attention；prefix LM 对前缀双向、对后续因果。

Encoder-only models are bidirectional and good for representations, decoder-only models are causal and generate natively, and encoder-decoders combine a bidirectional encoder with a causal decoder via cross-attention.

Decoder-only 占主导的论点（作为论点陈述，非定论）：

  1. 目标统一、训练信号密：NTP 每个位置都有 loss；任何任务都能写成"给定前文生成后文"，零样本/少样本/指令都自然。
  2. 简单、易扩展：一个栈、一种注意力、一套并行方案；scaling law 研究和基础设施都围绕它发展。
  3. 推理效率：KV cache 在多轮对话中可以复用；encoder-decoder 改变输入要重算 encoder。
  4. 经验结果：Wang et al. 2022 对比多种架构与目标，发现 causal decoder + 全语言建模在零样本泛化上（无多任务微调时）最好，而 encoder-decoder 在多任务微调后更强；
  5. 低秩论证（有争议）：有观点认为双向注意力矩阵可能退化为低秩，而因果的下三角注意力矩阵（对角元为正时）满秩，表达能力不受此限制。

反方/细节：同参数下 encoder-decoder 在条件生成（翻译、摘要）上常更高效；双向编码器对检索/分类仍是首选（embedding 模型）。"decoder-only 胜出"很大程度上也是路径依赖和工程生态。

Say it in English

I'd say decoder-only won for a mix of reasons rather than one decisive one. Next-token prediction gives a training signal at every position and casts every task as continuation, so the same model does zero-shot, few-shot and instruction following. The architecture is a single homogeneous stack, which is simple to scale and to serve, and the KV cache can be reused across turns. Empirically, causal decoders trained with plain language modeling had the best zero-shot generalization in controlled comparisons. That said, encoder-decoders can be more parameter-efficient for conditional generation, and bidirectional encoders are still the default for embeddings.

§7 · MIXTURE OF EXPERTSMoE：稀疏专家混合

前沿模型大量使用 MoE（Mixtral、DeepSeek-V2/V3、Qwen MoE、gpt-oss 等）。面试重点：路由怎么做、负载为什么会不均衡、怎么修、通信代价在哪、总参数 vs 激活参数。

★

Router、top-k、capacity factor、token dropping

一句话

把 FFN 换成 \(E\) 个专家 FFN + 一个线性 router；每个 token 只送往 router 分数最高的 \(k\) 个专家，输出按门控权重加权求和；总参数随 \(E\) 增长，但每 token 计算只随 \(k\) 增长。

An MoE layer replaces the MLP with many expert MLPs and a learned router that sends each token to its top-k experts, so total parameters scale with the number of experts while per-token compute scales only with k.

计算（token-choice top-k）：

$$p(x)=\mathrm{softmax}(W_rx)\in\mathbb{R}^E,\quad \mathcal{T}=\mathrm{TopK}(p,k),\quad y=\sum_{e\in\mathcal T}g_e(x)\,\mathrm{FFN}_e(x)$$

门控 \(g_e\) 可以是原 softmax 概率，或在选中的 \(k\) 个上重新归一化（Mixtral 先 top-k 再对这 \(k\) 个 logit 做 softmax）。router 通过门控权重接收梯度（top-k 选择本身不可微）。

为什么有效？同样的每 token FLOPs 下，参数（知识容量）多得多。Mixtral 8x7B：8 专家 top-2，总参数约 47B，激活约 13B（attention 等是共享的，所以不是 56B）。DeepSeek-V3：总 671B，激活 37B。

Capacity factor 与 token dropping。为了让 kernel 形状固定（尤其在 TPU/专家并行下），每个专家每个 batch 最多处理 \(\text{capacity}=\text{CF}\times\frac{k\cdot\#\text{tokens}}{E}\) 个 token。CF=1.0 表示刚好均分；常用 1.25。超出容量的 token 被丢弃（不经过该专家，只走残差连接），容量不足的专家补 padding 浪费计算。CF 越大丢得越少但浪费越多。较新的实现（如 MegaBlocks 的 dropless MoE）用分块稀疏矩阵乘避免丢 token。

Expert-choice routing（Zhou et al. 2022）：反过来让每个专家选 top-\(c\) 个 token，天然负载均衡，但对自回归推理不友好（一个 token 可能没被任何专家选中，且选择依赖于 batch 中的其他 token，破坏因果性）。

常见误区"Mixtral 8x7B = 56B 参数"——错，attention、embedding 是共享的，只有 FFN 有 8 份，约 47B。另外 MoE 节省的是 FLOPs，不节省显存：所有专家都必须装在（某些）GPU 上，推理时小 batch 下访存也更多。
Say it in English

A mixture-of-experts layer replaces the dense MLP with E expert MLPs and a small linear router. For each token, the router produces a softmax over experts, we pick the top k, usually one, two or eight, and the output is the gate-weighted sum of those experts' outputs. This decouples total parameters from per-token compute: you get the capacity of a huge model at the FLOPs of a small one. In practice each expert has a capacity, a capacity factor times the even share of tokens, and overflow tokens are dropped and just pass through the residual. The catch is that all experts must sit in memory and you need load balancing and all-to-all communication.

★

负载均衡：Switch aux loss、router z-loss、aux-loss-free

一句话

Router 有"富者愈富"的坍缩倾向；Switch 的辅助损失 \(\alpha E\sum_e f_eP_e\) 在均匀分配时取最小值 \(\alpha\)；z-loss 惩罚 router logit 的 logsumexp 平方以防数值爆炸；DeepSeek-V3 改用只影响选择的偏置项 \(b_e\) 动态调节，几乎不需要辅助损失。

Routers tend to collapse onto a few experts, so we add a load-balancing loss, alpha times E times the sum of dispatch fraction times mean router probability, plus a z-loss on router logits; DeepSeek-V3 instead adjusts a per-expert bias used only for selection.

为什么会坍缩？被选中多的专家得到更多梯度、变得更好、更常被选——正反馈。坍缩后大部分专家闲置（浪费参数），专家并行时某些 GPU 过载（慢）。

Switch Transformer 负载均衡损失

（Fedus et al. 2021）对一个 batch 的 \(N\) 个 token：

$$\mathcal{L}_{\text{aux}}=\alpha\cdot E\cdot\sum_{e=1}^{E}f_e\,P_e,\qquad f_e=\frac1N\sum_{x}\mathbb{1}[\arg\max p(x)=e],\qquad P_e=\frac1N\sum_x p_e(x)$$
  • \(f_e\)：实际分配给专家 \(e\) 的 token 比例（来自 argmax，不可微）；\(P_e\)：router 给专家 \(e\) 的平均概率（可微，梯度通过它流回 router）。
  • 均匀时 \(f_e=P_e=1/E\)，\(\sum_e f_eP_e=E\cdot\frac{1}{E^2}=\frac1E\)，乘 \(E\) 后损失 \(=\alpha\)（与 \(E\) 无关，这就是乘 \(E\) 的原因）。完全坍缩到一个专家时 \(=\alpha E\)。
  • 梯度直觉：\(\partial\mathcal L/\partial P_e\propto f_e\)，过载专家（\(f_e\) 大）的概率被压得更狠。
  • Switch 用 \(\alpha=10^{-2}\)。top-\(k\) 时 \(f_e\) 统计所有 \(k\) 个分配（通常再除以 \(k\) 归一化）。

Router z-loss

（ST-MoE, Zoph et al. 2022）\(\mathcal L_z=\frac1N\sum_x\big(\log\sum_e e^{z_e(x)}\big)^2\)，系数约 \(10^{-3}\)。惩罚过大的 router logit，减少 bf16 下 exp 的舍入误差和训练不稳定，几乎不损失质量。同样的 z-loss 思想也用于 LM head 输出 logit（PaLM）。

Fine-grained + shared experts（DeepSeekMoE）

（Dai et al. 2024）(1) 细粒度切分：把每个专家切成 \(m\) 个更小的专家，同时 top-k 变成 top-\(mk\)，计算量不变，但组合数大增，专家更专一；(2) 共享专家：若干个所有 token 都会经过的专家，承载通用知识，减少路由专家之间的冗余。DeepSeek-V3：每层 1 个共享 + 256 个路由专家，每 token 激活 8 个路由专家。

Auxiliary-loss-free 负载均衡（DeepSeek-V3）

辅助损失太大会损害主任务。DeepSeek-V3 给每个专家一个偏置 \(b_e\)，只在选 top-k 时加到亲和度分数上（\(s_e+b_e\)），门控权重仍用原分数 \(s_e\)。每个训练 step 结束时：专家过载则 \(b_e\leftarrow b_e-\gamma\)，欠载则 \(b_e\leftarrow b_e+\gamma\)（前 14.3T token 用 \(\gamma=0.001\)，最后 500B token 设为 0）。偏置不接收梯度，不干扰主目标。另外保留一个极小权重（\(\alpha=10^{-4}\)）的序列级平衡损失，防止单个序列内极端不均衡。V3 的亲和度用 sigmoid（而非 softmax），然后在选中的专家上归一化。

常见误区把 \(f_e\) 也当成可微量——它来自 argmax/top-k，没有梯度；损失的梯度全部经过 \(P_e\)。另一个误区：认为平衡损失能保证每个 batch 完美均衡——只是软约束，仍需 capacity 或 dropless 实现兜底。
Say it in English

Routers have a rich-get-richer dynamic: popular experts get more gradient, improve, and get picked even more. The Switch Transformer fixes this with an auxiliary loss, alpha times E times the sum over experts of f_e times P_e, where f_e is the fraction of tokens actually dispatched to expert e and P_e is the mean router probability for e. Only P_e is differentiable, and the gradient pushes down the probability of overloaded experts. The loss equals alpha at perfect balance. ST-MoE adds a router z-loss, the squared log-sum-exp of router logits, for numerical stability. DeepSeek-V3 goes further and replaces most of the auxiliary loss with a per-expert bias that's added only when selecting the top-k and is nudged up or down after each step depending on load.

Expert parallelism 与 all-to-all

一句话

把不同专家放在不同 GPU 上；每层 MoE 需要两次 all-to-all：先把每个 token 发到其专家所在的卡（dispatch），算完再发回（combine）。通信量与 token 数 × \(d\) × \(k\) 成正比，常常是 MoE 的瓶颈。

Expert parallelism shards experts across devices and needs two all-to-all exchanges per MoE layer, one to dispatch tokens and one to combine results.

数据并行切 batch、专家并行切专家。每张卡上的 token 根据路由结果打包发送给持有对应专家的卡，计算后发回原卡按门控加权。跨节点 all-to-all 带宽远低于 NVLink，所以 DeepSeek-V3 限制每个 token 最多路由到 4 个节点（node-limited routing），并设计了计算-通信重叠的流水线。推理时 MoE 的显存（所有专家）和小 batch 下的访存（不同 token 激活不同专家）是主要成本。详见 09。

Say it in English

With expert parallelism each device hosts a subset of experts. In every MoE layer, tokens are routed, then an all-to-all sends each token's hidden state to the devices holding its chosen experts, the experts run, and a second all-to-all returns the outputs to be combined. The communication volume scales with tokens times hidden size times k, and across nodes it can dominate step time, which is why systems like DeepSeek-V3 limit how many nodes a token can be routed to and overlap communication with computation.

Online softmax：递推推导

一句话

流式维护当前最大值 \(m\) 和归一化和 \(\ell=\sum e^{x_j-m}\)；遇到新值时 \(m'=\max(m,x)\)，\(\ell'=\ell\,e^{m-m'}+e^{x-m'}\)。一次遍历就得到稳定的 softmax 分母，并可分块并行合并。

Online softmax keeps a running max and a running sum, rescaling the sum by e to the old max minus new max whenever the max changes, so softmax can be computed in one streaming pass over blocks.

问题。稳定 softmax 需要三遍：(1) 求 \(m=\max_j x_j\)；(2) 求 \(\ell=\sum_j e^{x_j-m}\)；(3) 输出 \(e^{x_i-m}/\ell\)。对长序列，每遍都要从 HBM 读一次。

递推（Milakov & Gimelshein 2018）。定义前 \(t\) 个元素的 \(m_t=\max_{j\le t}x_j\)，\(\ell_t=\sum_{j\le t}e^{x_j-m_t}\)。则

$$m_t=\max(m_{t-1},x_t),\qquad \ell_t=\sum_{j\le t-1}e^{x_j-m_t}+e^{x_t-m_t}=\underbrace{\Big(\sum_{j\le t-1}e^{x_j-m_{t-1}}\Big)}_{\ell_{t-1}}e^{m_{t-1}-m_t}+e^{x_t-m_t}$$

初始化 \(m_0=-\infty,\ell_0=0\)。关键一步：\(e^{x_j-m_t}=e^{x_j-m_{t-1}}\cdot e^{m_{t-1}-m_t}\)。由于 \(m_t\ge m_{t-1}\)，缩放因子 \(\le1\)，数值稳定。

两个块的合并（并行版本）：\((m_A,\ell_A)\) 与 \((m_B,\ell_B)\) 合并为 \(m=\max(m_A,m_B)\)，\(\ell=\ell_Ae^{m_A-m}+\ell_Be^{m_B-m}\)。这个运算满足结合律，所以可以任意分块、树形归约。

推广到 attention 输出。我们要的其实是 \(o=\sum_j \mathrm{softmax}_j\,v_j\)。同样维护未归一化的累加器 \(\mathrm{acc}=\sum_j e^{s_j-m}v_j\)，每当最大值从 \(m\) 变成 \(m'\)，就把 \(\mathrm{acc}\) 乘 \(e^{m-m'}\) 再加新块的贡献；最后 \(o=\mathrm{acc}/\ell\)。这正是 FlashAttention 前向的核心。

代码：online softmax 与分块 attention（numpy，已运行）
def online_softmax_stats(xs):
    m, l = -np.inf, 0.0
    for x_ in xs:
        m_new = max(m, x_)
        l = l * np.exp(m - m_new) + np.exp(x_ - m_new)   # rescale old sum, add new term
        m = m_new
    return m, l

def flash_forward(q, k, v, Bc=16, causal=False):
    """Tiled attention for one head: never materializes the (Tq, Tk) matrix."""
    Tq, d = q.shape; Tk = k.shape[0]
    scale = 1 / np.sqrt(d)
    m = np.full(Tq, -np.inf); l = np.zeros(Tq); acc = np.zeros((Tq, v.shape[1]))
    for j in range(0, Tk, Bc):                          # stream over key/value blocks
        s = q @ k[j:j+Bc].T * scale                     # (Tq, Bc) scores for this block
        if causal:
            qi = np.arange(Tq)[:, None]; kj = np.arange(j, min(j+Bc, Tk))[None]
            s = np.where(kj <= qi, s, -np.inf)
        m_new = np.maximum(m, s.max(1))
        alpha = np.exp(m - m_new)                       # correction for previously seen blocks
        p = np.exp(s - m_new[:, None])
        l = l * alpha + p.sum(1)
        acc = acc * alpha[:, None] + p @ v[j:j+Bc]
        m = m_new
    return acc / l[:, None]

# verified: equals softmax(q k^T / sqrt(d)) v, with and without causal mask
Say it in English

The standard stable softmax needs a pass for the max, a pass for the sum, and a pass to normalize. Online softmax fuses the first two: I keep a running max m and a running sum l of exponentials relative to m. When a new element arrives, the new max is the larger of the two, and the old sum is multiplied by e to the old max minus the new max before adding the new term. The same rescaling applies to a running weighted sum of value vectors, and two partial results can be merged associatively, which is exactly what lets FlashAttention process attention block by block.

FlashAttention：IO-aware 精确注意力

一句话

注意力的瓶颈是 HBM 读写而非算力；FlashAttention 把 Q、K、V 切块载入片上 SRAM，用 online softmax 在块内完成全部计算，从不把 \(T\times T\) 矩阵写回 HBM；反向时重算注意力而非存储它。结果是精确的（不是近似），FLOPs 不变（反向还略多），但显存 \(O(T)\)、速度快数倍。

FlashAttention is exact attention that tiles Q, K and V into on-chip SRAM and uses online softmax so the T by T matrix never goes to HBM; it recomputes attention in the backward pass, trading extra FLOPs for far less memory traffic.

出自 Dao et al. 2022。

为什么朴素 attention 慢？GPU 存储层级：HBM（几十 GB，约 2–3 TB/s）与 SRAM（每个 SM 约百 KB 级，带宽高一个数量级以上）。朴素实现：算 \(S=QK^\top\) 写回 HBM → 读 \(S\) 做 softmax 写回 \(P\) → 读 \(P\) 算 \(PV\)。\(S,P\) 都是 \(O(T^2)\)，读写量远大于 \(Q,K,V\) 本身。softmax、mask、dropout 都是逐元素操作，算术强度极低，被访存卡住。

算法（前向）。

  1. 把 \(Q\) 切成行块 \(Q_i\)（大小 \(B_r\)），\(K,V\) 切成块 \(K_j,V_j\)（大小 \(B_c\)），块大小按 SRAM 容量选。
  2. 对每个 \(Q_i\)：在 SRAM 中维护 \(m_i,\ell_i,\mathrm{acc}_i\)；遍历所有 \(K_j,V_j\)：算 \(S_{ij}=Q_iK_j^\top/\sqrt d\)，按 online softmax 更新统计量与累加器（见上一节代码）。
  3. 最后 \(O_i=\mathrm{acc}_i/\ell_i\) 写回 HBM，同时保存 logsumexp \(L_i=m_i+\log\ell_i\)（每行一个标量）供反向使用。

反向：重算（recomputation）。标准反向需要存 \(P\)（\(O(T^2)\)）。FlashAttention 只存 \(O\) 和 \(L\)，反向时用 \(Q,K,V\) 和 \(L\) 分块重新算出 \(P_{ij}=\exp(S_{ij}-L_i)\)。多做了一次 \(QK^\top\)，但避免了 \(O(T^2)\) 的 HBM 读写，反而更快。这是"用计算换访存"的典型例子，与 activation checkpointing 同理。

IO 复杂度。论文给出 HBM 访问量 \(\Theta(T^2d^2/M)\)（\(M\) 为 SRAM 大小），而标准实现是 \(\Theta(Td+T^2)\)；对典型 \(d\) 和 \(M\)，\(d^2/M\ll1\)，访问量少很多倍。

后续版本。

  • FlashAttention-2（2023）：减少非矩阵乘 FLOPs（例如把除以 \(\ell\) 推迟到最后）、在序列长度维度上也并行（不只是 batch×head）、改进 warp 间分工减少共享内存读写。约 2× 加速，A100 上达到理论峰值的 50–73%。
  • FlashAttention-3（2024，Hopper/H100）：利用 Tensor Core 与 TMA 的异步性做 warp specialization（生产者/消费者 warp）、块间交错 matmul 与 softmax、FP8 低精度（块量化 + incoherent processing 降低误差）。FP16 下约 740 TFLOPs/s（约 75% 利用率），FP8 接近 1.2 PFLOPs/s。
  • Flash-Decoding：解码时 query 只有 1 个，改为沿 KV 长度维度切分并行，再合并（用的就是 online softmax 的合并公式）。见 08。
常见误区
  • "FlashAttention 是近似注意力 / 降低了复杂度"——错，它是精确的，FLOPs 仍是 \(O(T^2d)\)，只是 IO 和显存优化。
  • "FlashAttention 减少了 FLOPs"——反向因为重算还多了。
  • 忘记反向需要保存 logsumexp \(L\)。
Say it in English

FlashAttention starts from the observation that attention is memory-bound, not compute-bound: the naive version writes the T by T score matrix to HBM, reads it back for the softmax, writes the probabilities, and reads them again for the value product. FlashAttention tiles Q, K and V into blocks that fit in on-chip SRAM, and for each query block it streams over key-value blocks, using the online softmax recurrence to maintain a running max, normalizer and output accumulator. The full attention matrix never touches HBM, so memory is linear in sequence length. In the backward pass it stores only the output and the log-sum-exp per row and recomputes the attention probabilities block by block. It's exact, the FLOPs are the same or slightly higher, but wall-clock is several times faster.

追问链

    思路
    GPU 算力增长远快于带宽，现代 GPU 每读一个字节可以做几百次 FLOP。重算 \(QK^\top\) 是高算术强度的 GEMM，在 SRAM 中完成；而存/读 \(O(T^2)\) 的 \(P\) 是低算术强度的 HBM 流量。同时省下的 \(O(T^2)\) 显存允许更长序列和更大 batch。

    思路

线性注意力：核技巧与递推形式

一句话

把 \(\exp(q\cdot k)\) 换成特征映射内积 \(\phi(q)^\top\phi(k)\)，利用结合律先算 \(\sum_j\phi(k_j)v_j^\top\)，复杂度变成 \(O(Td^2)\)；因果版本等价于一个状态为 \(d\times d\) 矩阵的 RNN，解码每步 \(O(1)\)。

Linear attention replaces the softmax kernel with a feature-map inner product, so by associativity the causal version becomes an RNN with a d by d matrix state and constant cost per token.

（Katharopoulos et al. 2020, Transformers are RNNs）

$$o_i=\frac{\sum_{j\le i}\phi(q_i)^\top\phi(k_j)\,v_j}{\sum_{j\le i}\phi(q_i)^\top\phi(k_j)}=\frac{\phi(q_i)^\top\overbrace{\textstyle\sum_{j\le i}\phi(k_j)v_j^\top}^{S_i\in\mathbb{R}^{d_k\times d_v}}}{\phi(q_i)^\top\underbrace{\textstyle\sum_{j\le i}\phi(k_j)}_{z_i}}$$

递推：\(S_i=S_{i-1}+\phi(k_i)v_i^\top\)，\(z_i=z_{i-1}+\phi(k_i)\)。训练时可以用并行（矩阵）形式或分块（chunkwise）形式，推理时用递推形式，状态大小固定——没有随长度增长的 KV cache。常用 \(\phi(x)=\mathrm{elu}(x)+1\)。我们数值验证了并行形式与递推形式完全相等。

弱点：固定大小的状态是"有损压缩"，精确检索/复制（如 "在长文中找出某个电话号码"）能力明显弱于 softmax attention；没有 softmax 的尖锐选择。后续工作加入衰减/门控（RetNet、GLA、Mamba-2）和 delta rule（DeltaNet，按"误差"更新状态）来改善。

Say it in English

Linear attention swaps the exponential similarity for an inner product of feature maps, phi of q dot phi of k. Then by associativity you can sum phi of k times v transpose over the keys first, so cost becomes linear in sequence length. In the causal case this is literally an RNN: the state is a d by d matrix updated by adding phi of k_t times v_t transpose each step, so decoding is constant time and memory. The trade-off is that a fixed-size state is lossy, so exact retrieval and copying over long contexts are much weaker than with softmax attention; gating, decay and delta-rule updates are the modern fixes.

SSM / Mamba、混合架构、稀疏注意力（简介）

一句话

Mamba 是输入相关（selective）的状态空间模型，线性时间、常数解码状态；纯 SSM 在召回类任务上弱，所以实际大模型多用"少量 attention 层 + 大量线性/SSM 层"的混合架构。

Mamba is a selective state-space model with linear-time training and constant-size decoding state; in practice hybrids that keep a few attention layers among many linear or SSM layers work best.

SSM：连续系统 \(h'(t)=Ah(t)+Bx(t)\)，\(y=Ch\)，离散化后是线性 RNN \(h_t=\bar Ah_{t-1}+\bar Bx_t\)。S4 等用固定参数（可以写成长卷积并行训练）。Mamba（Gu & Dao 2023）让 \(B,C,\Delta\) 依赖输入（selective），从而能"选择性记住/遗忘"，失去卷积形式后用硬件感知的并行 scan 训练。Mamba-2 揭示了 SSM 与（带衰减的）线性注意力的对偶关系。

混合架构例子：Jamba（Transformer 与 Mamba 层以 1:7 交错，加 MoE）；MiniMax-01（lightning attention 线性注意力为主，每 7 层线性注意力后接 1 层 softmax attention）。动机：线性层处理大部分 token 混合以节省长上下文成本，少量全注意力层负责精确检索。

稀疏注意力：固定模式（局部 + 全局 token，如 Longformer、BigBird）；可学习/内容相关的块选择（例如 DeepSeek 的 NSA 等"原生稀疏注意力"研究方向）。核心问题始终是：如何在 \(o(T^2)\) 的代价下保留精确检索能力。

Say it in English

State-space models like Mamba are linear recurrences whose transition parameters depend on the input, so the model can choose what to keep in its fixed-size state. They train in parallel with a hardware-aware scan and decode in constant time per token. Their weakness, like linear attention, is exact recall over long contexts. That's why most production-scale efforts that use them are hybrids: mostly linear or SSM layers for cheap mixing, plus a few full softmax attention layers for precise retrieval.

BPE：训练与编码，一步一步

一句话

训练：从字符（或字节）开始，反复统计语料中最频繁的相邻符号对并合并成新符号，记录合并顺序，直到达到词表大小。编码：对新词从字符开始，按训练时的合并顺序（优先级）依次应用合并。

BPE training repeatedly merges the most frequent adjacent pair of symbols and records the merge order; encoding applies those merges to new text in the same priority order.

（Sennrich et al. 2016 把 BPE 引入 NMT）

手动示例

语料（词 → 频次）：low:5, lower:2, newest:6, widest:3，每个词末尾加 </w>。

  1. 初始：l o w </w>(5)，l o w e r </w>(2)，n e w e s t </w>(6)，w i d e s t </w>(3)。
  2. 统计相邻对：(e,s)=6+3=9，(s,t)=9，(t,</w>)=9，(l,o)=7，(o,w)=7，(w,e)=8 …… 最高频为 9，三者并列；按字典序打破平局选 (e,s) → 合并 1：es。
  3. 更新后 (es,t)=9 最高 → 合并 2：est。
  4. (est,</w>)=9 → 合并 3：est</w>（词尾的 "est"）。
  5. (l,o)=7，(o,w)=7 并列 → 合并 4：lo。

编码新词 lowest：l o w e s t </w> → 按优先级 es → est → est</w> → lo，得到 [lo, w, est</w>]。编码 newer：没有适用合并（(e,r) 未学过），保持字符级 [n, e, w, e, r, </w>]。

编码时为什么要按合并顺序，而不是贪心最长匹配？BPE 的定义就是按学到的顺序重放合并；最长匹配（WordPiece 的做法）可能得到不同切分。实现时每一步找当前序列中 rank 最小的相邻对合并，朴素实现 \(O(n^2)\)。

代码：BPE 训练与编码（纯 Python，已运行）
from collections import Counter

def train_bpe(words, num_merges):
    """words: dict word -> count. Each word is split into chars + end marker '</w>'."""
    vocab = {tuple(w) + ("</w>",): c for w, c in words.items()}
    merges = []
    for _ in range(num_merges):
        pairs = Counter()
        for sym, c in vocab.items():
            for a, b in zip(sym, sym[1:]):
                pairs[(a, b)] += c
        if not pairs:
            break
        best = min(pairs, key=lambda p: (-pairs[p], p))  # most frequent; ties -> lexicographically smallest
        merges.append(best)
        new_vocab = {}
        for sym, c in vocab.items():
            out, i = [], 0
            while i < len(sym):
                if i < len(sym) - 1 and (sym[i], sym[i + 1]) == best:
                    out.append(sym[i] + sym[i + 1]); i += 2
                else:
                    out.append(sym[i]); i += 1
            new_vocab[tuple(out)] = c
        vocab = new_vocab
    return merges, vocab

def encode(word, merges):
    """Apply merges in the order they were learned (rank = priority)."""
    sym = list(word) + ["</w>"]
    rank = {p: i for i, p in enumerate(merges)}
    while len(sym) > 1:
        pairs = [(rank.get((a, b), float("inf")), i) for i, (a, b) in enumerate(zip(sym, sym[1:]))]
        r, i = min(pairs)
        if r == float("inf"):
            break
        sym[i:i + 2] = [sym[i] + sym[i + 1]]
    return sym

if __name__ == "__main__":
    corpus = {"low": 5, "lower": 2, "newest": 6, "widest": 3}
    merges, vocab = train_bpe(corpus, 4)
    print(merges)
    print(vocab)
    assert merges[:3] == [("e", "s"), ("es", "t"), ("est", "</w>")]
    print(encode("lowest", merges), encode("newer", merges))
    assert "".join(encode("lowest", merges)) == "lowest</w>"

输出：merges = [('e','s'), ('es','t'), ('est','</w>'), ('l','o')]；encode('lowest') = ['lo','w','est</w>']。

Say it in English

BPE training starts from a base vocabulary of characters, or bytes in byte-level BPE, counts all adjacent symbol pairs in the corpus weighted by frequency, merges the most frequent pair into a new symbol, and repeats until the vocabulary reaches the target size. The ordered list of merges is the tokenizer. To encode new text, you split into base symbols and repeatedly apply the highest-priority merge that appears, in the same order they were learned. Frequent words end up as single tokens, and rare words decompose into subwords, so there are no out-of-vocabulary tokens.

SentencePiece（Kudo & Richardson 2018）：不依赖语言相关的预分词，把空格替换成 ▁ 当普通字符，所以解码可逆、对中文日文等无空格语言友好。LLaMA-1/2 使用 SentencePiece BPE（32k 词表，带 byte fallback：未知字符退回字节）。Unigram（Kudo 2018）。

Say it in English

Byte-level BPE runs BPE on UTF-8 bytes, so the base vocabulary is 256 and any string can be encoded with no unknown token; GPT-2 onward also pre-splits with a regex so merges don't cross word or digit boundaries. WordPiece, used in BERT, chooses merges by likelihood gain rather than raw frequency and encodes greedily by longest match. Unigram goes top-down: it starts from a big vocabulary, fits a unigram language model, and prunes the pieces that least affect likelihood, then segments with Viterbi. SentencePiece is the library that treats whitespace as an ordinary symbol and supports both BPE and Unigram.

词表大小权衡与 tokenizer 伪影

一句话

词表大 → 序列短（省 attention 和推理步数）、多语言更公平，但 embedding/LM head 参数多、softmax 贵、稀有 token 训练不足；小词表则反之。很多怪现象（数字、空格、拼写、多语言成本、glitch token）来自 tokenizer。

A larger vocabulary shortens sequences but costs embedding parameters, softmax compute and undertrained rare tokens; many model quirks with numbers, spelling and multilingual cost trace back to tokenization.

趋势：GPT-2 约 50k，LLaMA-2 32k，LLaMA-3 128k，Gemma 256k。更大词表对多语言和代码更省 token。

常见伪影：

  • 数字：不同长度数字被切得不规律（"1234" 可能是 "123"+"4"），算术困难；LLaMA 系把数字拆成单个数字，GPT-4 的 tokenizer 把数字按最多 3 位一组切分。
  • 空格/大小写：" hello" 和 "hello" 是不同 token；prompt 末尾多一个空格可能显著改变输出（token healing 问题）。
  • 拼写/字符级任务：模型看不到 token 内部字符（"strawberry 有几个 r"）。
  • 多语言 fertility：每个词平均 token 数（fertility）在低资源语言上高好几倍 → 更贵、更短的有效上下文、更差的表现。
  • Glitch tokens：tokenizer 语料中高频、但模型训练语料中几乎没出现的 token（如著名的 "SolidGoldMagikarp"，来自 Reddit 用户名），其 embedding 几乎没被训练，输入时引发怪异行为。根源是 tokenizer 训练数据与模型训练数据不一致。
  • 评估：不同 tokenizer 的困惑度不可直接比较，应换算成 bits-per-byte（见 05）。
Say it in English

Vocabulary size is a trade-off. A bigger vocabulary compresses text into fewer tokens, which saves attention cost and decoding steps and is fairer to non-English languages, but it adds embedding and output-layer parameters and leaves rare tokens undertrained. Tokenization also explains many quirks: inconsistent digit chunking hurts arithmetic, the model can't see characters inside a token so spelling tasks are hard, trailing spaces change the token sequence, and glitch tokens appear when a token was frequent in the tokenizer's training data but almost absent from the model's.

稳定性技巧：QK-norm、logit soft-capping、z-loss

一句话

大模型训练中 attention logit 和输出 logit 会增长导致不稳定；QK-norm 在点积前对 q、k 做归一化，soft-capping 用 \(c\cdot\tanh(z/c)\) 把 logit 平滑限制在 \((-c,c)\)，z-loss 惩罚 \(\log Z\) 偏离 0。

QK-norm normalizes queries and keys before the dot product, soft-capping squashes logits with c times tanh of z over c, and z-loss penalizes the log partition function, all to stop logit growth from destabilizing training.

  • Attention logit 增长：ViT-22B（Dehghani et al. 2023）报告 attention logit 失控增长导致 attention 熵接近 0、训练发散，引入 QK-norm（对 q、k 做 LayerNorm）解决。之后 OLMo 2、Gemma 3 等也采用 QK-norm。
  • Logit soft-capping：Gemma 2 对 attention logit（cap = 50）和最终输出 logit（cap = 30）做 \(z\leftarrow c\tanh(z/c)\)。小 \(z\) 时近似恒等，大 \(z\) 时饱和。缺点：与标准 FlashAttention kernel 不直接兼容（需要支持 softcap 的 kernel）。Gemma 3 用 QK-norm 取代了 Gemma 2 的 attention soft-capping。
  • z-loss：\(\mathcal L_z=10^{-4}\cdot(\log Z)^2\)（PaLM 对输出 softmax 使用），鼓励 \(\log Z\approx0\)，防止输出 logit 漂移；MoE router 也用（§7）。
  • LN epsilon 与 bf16：bf16 只有 8 位有效尾数（约 2–3 位十进制有效数字），在 bf16 里计算方差会严重舍入；标准做法是 norm 内部升到 fp32 计算再转回。\(\epsilon\) 常为 1e-5（LLaMA-2 RMSNorm）或 1e-6；当某些 token 的激活非常小时，\(\epsilon\) 的相对大小会影响输出，epsilon 太小可能导致除以极小数放大噪声。
Say it in English

A common failure in large-scale training is logit growth: query and key norms grow, attention entropy collapses toward one-hot, and loss spikes. QK-norm fixes this by normalizing queries and keys before the dot product, which bounds the logits. Gemma 2 instead soft-capped logits with c times tanh of z over c, at fifty for attention and thirty for the final logits, and Gemma 3 switched to QK-norm. For the output softmax, z-loss adds a small penalty on the squared log partition function to keep logits from drifting. And norms are computed in fp32 even when the model runs in bf16.

无 bias、无 dropout、embedding scaling、初始化

一句话

现代 LLM 线性层通常去掉 bias（PaLM 报告提升大模型训练稳定性，省参数）；预训练不用 dropout（单 epoch、数据量远大于参数，不会过拟合）；部分模型给 embedding 乘 \(\sqrt d\)；残差输出投影按深度缩小初始化（GPT-2：\(1/\sqrt{2L}\)）。

Modern LLMs drop biases for stability, skip dropout because single-epoch pretraining doesn't overfit, sometimes scale embeddings by root d, and shrink the initialization of residual output projections with depth.

  • 无 bias：PaLM 论文称去掉所有 dense 层和 LayerNorm 的 bias 提升了大模型训练稳定性。bias 在有 norm 的网络里作用有限，而且对 KV cache 无影响但增加了实现复杂度。（注：Qwen 系列保留了 QKV 投影的 bias，说明这不是铁律。）
  • 无 dropout：预训练只过数据约 1 遍，训练 loss ≈ 验证 loss，没有过拟合；dropout 只会降低有效容量和吞吐。微调小数据时可能会加回。
  • Embedding scaling：原始 Transformer 与 Gemma 把 embedding 输出乘 \(\sqrt{d}\)，因为 tied embedding 的初始化标准差较小（\(\sim1/\sqrt d\)），乘 \(\sqrt d\) 使输入尺度与位置编码/残差流匹配。
  • 初始化：常用 \(\mathcal N(0,0.02^2)\)；GPT-2 将每个残差分支的输出投影（\(W_O\)、\(W_2\)）再乘 \(1/\sqrt{2L}\)（每层有 2 个残差加），使残差流方差不随深度线性增长。更系统的方案是 μP（见 05）。
  • KV cache：推理时缓存每层已计算的 K、V，每步只算新 token；系统细节（PagedAttention、量化、驱逐）见 08。
Say it in English

Most modern LLMs remove biases from linear layers and norms; PaLM reported it improved training stability at scale, and it simplifies things. They also use no dropout in pretraining, since you see each token about once and the model is far from overfitting, so dropout just wastes capacity. Some models multiply embeddings by root d to match scales when weights are tied. And residual output projections are initialized smaller as depth increases, like GPT-2's one over root two L, so the residual stream variance doesn't blow up with depth.

Looped / recurrent-depth Transformer

一句话

让同一组层（或整个 block 栈）权重共享、循环多次，计算深度与参数量解耦；可以按输入难度自适应地决定循环次数，是"潜空间推理"的一条路线。

Looped transformers reuse the same layers for multiple iterations, decoupling compute depth from parameter count and allowing adaptive computation, which connects to latent reasoning.

Universal Transformer（Dehghani et al. 2018）：所有层共享权重、在深度上循环，并用 ACT（Adaptive Computation Time）让每个位置决定何时停止。ALBERT 也做跨层共享以压缩参数。近年的循环深度模型把"多想几步"放在潜空间而不是生成更多 token，与显式 CoT 形成对比。详见 07 推理能力 的潜空间推理一节。

延伸阅读：Ouro / Looped LMs（arXiv 2510.25741）。

Say it in English

A looped or recurrent-depth transformer applies the same block several times, so you can increase effective depth without adding parameters, and in principle choose the number of iterations per input, like the adaptive computation time in the Universal Transformer. It's one way to do reasoning in latent space rather than through generated chain-of-thought tokens, and the open questions are training stability, how to learn when to stop, and whether it scales as well as adding parameters.

SDPA（causal + padding mask）

一句话

四行核心：scores = q @ k.transpose(-2,-1) / sqrt(dh) → masked_fill(-inf) → softmax(dim=-1) → @ v。causal mask 用右下角对齐，KV cache 解码时也正确。

Scores, mask with minus infinity, softmax over keys, multiply by values; align the causal mask to the bottom-right so it also works with a KV cache.

import math
import torch
import torch.nn as nn
import torch.nn.functional as F

def sdpa(q, k, v, causal=True, key_padding_mask=None):
    """q: (B, H, Tq, dh); k, v: (B, H, Tk, dh); key_padding_mask: (B, Tk) bool, True = real token."""
    dh = q.size(-1)
    scores = q @ k.transpose(-2, -1) / math.sqrt(dh)            # (B, H, Tq, Tk)
    Tq, Tk = scores.shape[-2:]
    if causal:
        # query i sits at absolute position Tk - Tq + i and may see keys j <= that position.
        # (bottom-right alignment: also correct when decoding with a KV cache, Tq < Tk)
        allowed = torch.ones(Tq, Tk, dtype=torch.bool, device=q.device).tril(diagonal=Tk - Tq)
        scores = scores.masked_fill(~allowed, float('-inf'))
    if key_padding_mask is not None:
        scores = scores.masked_fill(~key_padding_mask[:, None, None, :], float('-inf'))
    attn = scores.softmax(dim=-1)                                 # normalize over KEYS (last dim)
    return attn @ v, attn                                         # (B, H, Tq, dh)

Say it in English

I compute scores as q times k transpose over root d_h, giving batch, heads, query length, key length. For the causal mask I build a lower-triangular boolean matrix aligned to the bottom-right, so when I decode one query against a cache of keys it can still see everything. Masked positions get minus infinity, then softmax over the last dimension, the keys, and multiply by v.

RoPE（rotate_half 与复数两种写法）

一句话

预计算 \(\cos(m\theta_i),\sin(m\theta_i)\)，x*cos + rotate_half(x)*sin；复数写法是 view_as_complex 后乘 \(e^{im\theta}\)。两种布局差一个固定置换。

Precompute cos and sin of position times frequency, then x times cos plus rotate-half of x times sin; the complex version multiplies pairs by e to the i m theta.

def rope_cache(T, dh, base=10000.0, device=None):
    inv_freq = base ** (-torch.arange(0, dh, 2, device=device).float() / dh)  # theta_i, (dh/2,)
    pos = torch.arange(T, device=device).float()
    ang = torch.outer(pos, inv_freq)                 # (T, dh/2): angle = m * theta_i
    ang = torch.cat([ang, ang], dim=-1)              # (T, dh): "half-split" layout (HF LLaMA)
    return ang.cos(), ang.sin()

def rotate_half(x):
    x1, x2 = x.chunk(2, dim=-1)                      # pair dim i with dim i + dh/2
    return torch.cat([-x2, x1], dim=-1)

def apply_rope(x, cos, sin):
    """x: (B, H, T, dh); cos, sin: (T, dh), broadcast over B and H."""
    return x * cos + rotate_half(x) * sin

def apply_rope_complex(x, base=10000.0):
    """Same rotation in the 'interleaved' layout (pairs (0,1), (2,3), ...), as in Meta's original LLaMA code."""
    *lead, T, dh = x.shape
    inv_freq = base ** (-torch.arange(0, dh, 2).float() / dh)
    ang = torch.outer(torch.arange(T).float(), inv_freq)                 # (T, dh/2)
    rot = torch.polar(torch.ones_like(ang), ang)                         # e^{i m theta}
    xc = torch.view_as_complex(x.float().reshape(*lead, T, dh // 2, 2).contiguous())  # (..., T, dh/2)
    return torch.view_as_real(xc * rot).flatten(-2).type_as(x)

Multi-head attention（支持 GQA / MQA）

一句话

投影 → view(B,T,H,dh).transpose(1,2) → RoPE → repeat_interleave 扩展 KV 头 → SDPA → transpose(1,2).contiguous().view(B,T,d) → wo。

Project, split heads, apply RoPE, expand KV heads for GQA, attend, merge heads, output projection.

class Attention(nn.Module):
    """Causal self-attention. n_kv_heads = n_heads -> MHA; 1 -> MQA; in between -> GQA."""
    def __init__(self, d_model, n_heads, n_kv_heads=None):
        super().__init__()
        self.h = n_heads
        self.h_kv = n_kv_heads or n_heads
        assert d_model % n_heads == 0 and n_heads % self.h_kv == 0
        self.dh = d_model // n_heads
        self.wq = nn.Linear(d_model, self.h * self.dh, bias=False)
        self.wk = nn.Linear(d_model, self.h_kv * self.dh, bias=False)
        self.wv = nn.Linear(d_model, self.h_kv * self.dh, bias=False)
        self.wo = nn.Linear(self.h * self.dh, d_model, bias=False)

    def forward(self, x, cos=None, sin=None):
        B, T, _ = x.shape
        q = self.wq(x).view(B, T, self.h, self.dh).transpose(1, 2)       # (B, H, T, dh)
        k = self.wk(x).view(B, T, self.h_kv, self.dh).transpose(1, 2)    # (B, Hkv, T, dh)
        v = self.wv(x).view(B, T, self.h_kv, self.dh).transpose(1, 2)
        if cos is not None:                                               # RoPE on q and k only
            q, k = apply_rope(q, cos, sin), apply_rope(k, cos, sin)
        rep = self.h // self.h_kv
        if rep > 1:   # query heads [g*rep, (g+1)*rep) share KV head g
            k = k.repeat_interleave(rep, dim=1)
            v = v.repeat_interleave(rep, dim=1)
        out, _ = sdpa(q, k, v, causal=True)                               # (B, H, T, dh)
        out = out.transpose(1, 2).contiguous().view(B, T, self.h * self.dh)  # concat heads
        return self.wo(out)                                               # mix heads
常见误区repeat_interleave 与 repeat 不同：前者得到 [k0,k0,k1,k1,…]（query 头 0、1 共享 KV 头 0），后者得到 [k0,k1,k0,k1,…]。只要训练和推理一致都"能用"，但加载预训练权重时必须与原实现一致（HF LLaMA 用的是 repeat_interleave 语义）。

RMSNorm 与 SwiGLU

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(d))     # gain only, no bias, no mean-centering

    def forward(self, x):
        xf = x.float()                                # do the reduction in fp32 even under bf16
        xf = xf * torch.rsqrt(xf.pow(2).mean(-1, keepdim=True) + self.eps)
        return xf.type_as(x) * self.weight

class SwiGLU(nn.Module):
    def __init__(self, d, hidden=None, multiple_of=256):
        super().__init__()
        hidden = hidden or int(8 * d / 3)             # 8/3 d keeps params ~= a 4d two-matrix FFN
        hidden = multiple_of * ((hidden + multiple_of - 1) // multiple_of)  # round up for hardware
        self.w1 = nn.Linear(d, hidden, bias=False)    # gate projection
        self.w3 = nn.Linear(d, hidden, bias=False)    # up projection
        self.w2 = nn.Linear(hidden, d, bias=False)    # down projection

    def forward(self, x):
        return self.w2(F.silu(self.w1(x)) * self.w3(x))

自测：SwiGLU(4096) 的隐藏维度为 11008（\(\frac83\cdot4096=10922\to\) 向上取整到 256 的倍数），与 LLaMA-7B 一致；RMSNorm 输出每个 token 的均方 ≈ 1。

Decoder block 与 tiny GPT

一句话

Pre-Norm block：x = x + attn(norm1(x)); x = x + mlp(norm2(x))；模型：embedding → blocks → final norm → (tied) head → cross-entropy。

Pre-norm block with residuals, then embedding, blocks, final norm, tied head and cross-entropy.

class Block(nn.Module):
    def __init__(self, d, n_heads, n_kv_heads=None):
        super().__init__()
        self.norm1 = RMSNorm(d)
        self.attn = Attention(d, n_heads, n_kv_heads)
        self.norm2 = RMSNorm(d)
        self.mlp = SwiGLU(d)

    def forward(self, x, cos, sin):
        x = x + self.attn(self.norm1(x), cos, sin)    # Pre-Norm: normalize only the branch input
        x = x + self.mlp(self.norm2(x))               # residual stream x itself is never normalized
        return x

class TinyGPT(nn.Module):
    def __init__(self, vocab, d=128, n_layers=4, n_heads=4, n_kv_heads=2, max_T=256, tie=True):
        super().__init__()
        self.tok = nn.Embedding(vocab, d)
        self.blocks = nn.ModuleList([Block(d, n_heads, n_kv_heads) for _ in range(n_layers)])
        self.norm = RMSNorm(d)                        # final norm before the LM head
        self.head = nn.Linear(d, vocab, bias=False)
        if tie:
            self.head.weight = self.tok.weight        # weight tying: one (V, d) matrix
        cos, sin = rope_cache(max_T, d // n_heads)
        self.register_buffer('cos', cos, persistent=False)
        self.register_buffer('sin', sin, persistent=False)
        self.apply(self._init)

    @staticmethod
    def _init(m):
        if isinstance(m, (nn.Linear, nn.Embedding)):
            nn.init.normal_(m.weight, mean=0.0, std=0.02)

    def forward(self, idx, targets=None):
        B, T = idx.shape
        x = self.tok(idx)                             # (B, T, d)
        cos, sin = self.cos[:T], self.sin[:T]
        for blk in self.blocks:
            x = blk(x, cos, sin)
        logits = self.head(self.norm(x))              # (B, T, V)
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1))
        return logits, loss

class MoE(nn.Module):
    """Token-choice top-k MoE FFN with Switch-style balance loss and router z-loss."""
    def __init__(self, d, n_experts=8, k=2, hidden=None):
        super().__init__()
        self.k, self.E = k, n_experts
        self.router = nn.Linear(d, n_experts, bias=False)
        self.experts = nn.ModuleList([SwiGLU(d, hidden) for _ in range(n_experts)])

    def forward(self, x):
        B, T, D = x.shape
        xf = x.reshape(-1, D)                                    # (N, D), N = B*T tokens
        logits = self.router(xf)                                 # (N, E)
        probs = logits.softmax(-1)
        topv, topi = probs.topk(self.k, dim=-1)                  # (N, k)
        gate = topv / topv.sum(-1, keepdim=True)                 # renormalize over the chosen k
        out = torch.zeros_like(xf)
        for e, expert in enumerate(self.experts):
            tok, slot = (topi == e).nonzero(as_tuple=True)       # tokens routed to expert e
            if tok.numel() == 0:
                continue
            out.index_add_(0, tok, gate[tok, slot].unsqueeze(-1) * expert(xf[tok]))
        # f_e: fraction of routing assignments to e (not differentiable); P_e: mean router prob (differentiable)
        counts = torch.zeros(self.E, device=x.device).scatter_add_(
            0, topi.flatten(), torch.ones(topi.numel(), device=x.device))
        f = counts / topi.numel()
        P = probs.mean(0)
        aux_loss = self.E * (f * P).sum()                        # == 1 when perfectly uniform
        z_loss = torch.logsumexp(logits, dim=-1).pow(2).mean()   # keeps router logits small
        return out.view(B, T, D), aux_loss, z_loss

自测：与逐 token 的稠密循环参考实现输出一致；aux_loss + z_loss 能把梯度传回 router。这个"按专家循环 + index_add_"的写法便于面试手写；生产实现会用排序 + 分组 GEMM（grouped GEMM）或 block-sparse kernel。
